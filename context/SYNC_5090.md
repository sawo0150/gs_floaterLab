# 5090 안전 동기화 가이드

이 문서는 로컬 워크스테이션과 `colin` 5090 서버가 서로의 작업을
덮어쓰거나 잃지 않고 `gs_floaterLab`과 `VIGS-SLAM`을 교환하는 절차다.

## 구조

```text
로컬 worktree ──push/fetch──┐
                             ├─ 5090 bare Git hub (작업 파일 없음)
5090 worktree ──push/fetch──┘

5090 results ──rsync, no-delete──> 로컬 results/5090_mirror/
```

5090의 bare 저장소는 다음 두 곳이다.

- `/home/intern/git-sync/gs_floaterLab.git`
- `/home/intern/git-sync/VIGS-SLAM-custom.git`

양쪽 worktree의 동기화 remote 이름은 `colin-sync`다. GitHub용 `origin` 또는
`custom` remote와 독립적이므로 이 절차는 GitHub에 push하지 않는다. Bare 저장소는
non-fast-forward push와 branch 삭제를 거부한다. 따라서 같은 이름의 branch가 갈라지면
한쪽 이력이 덮이는 대신 push가 실패한다.

`context/experiments/5090branch/`는 2026-09-14 이전 5090 파일의 일회성
보존 스냅샷이다. 앞으로의 변경을 이 폴더에 반복 복사하지 말고 작업 branch로 교환한다.

## 매 작업 시작

두 저장소의 상태를 확인한다.

```bash
cd /home/wosas/Desktop/Incremental_mapping_test/gs_floaterLab
scripts/sync_5090.sh status
scripts/sync_5090.sh fetch
```

5090에서는 경로만 다르고 명령은 같다.

```bash
cd /home/intern/gs_floaterLab
scripts/sync_5090.sh status
scripts/sync_5090.sh fetch
```

`fetch`는 commit/ref만 받으며 현재 branch, 소스 파일, 미추적 결과를 수정하지 않는다.

## 새 작업 시작

반드시 `main`에서 직접 작업하지 않고 고유 topic branch를 만든다.

```bash
scripts/sync_5090.sh new-work lab exp87-streaming-audit
scripts/sync_5090.sh new-work vigs exp87-streaming-audit
```

생성 이름은 각각 `work/<hostname>/exp87-streaming-audit`다. 명령은 먼저
`colin-sync/main`을 fetch하고 그 commit에서 시작한다. 추적 파일이 dirty하면 branch
전환을 중단한다. 미추적 대용량 결과는 건드리지 않지만, 새 branch의 추적 파일과 경로가
겹치면 Git 자체가 전환을 거부한다.

VIGS 경로를 자동으로 찾지 못하면 명시한다.

```bash
VIGS_REPO=/path/to/VIGS-SLAM scripts/sync_5090.sh new-work vigs exp87
```

## 작업 공유

먼저 소스·설정·exp 카드만 commit한다. PLY, checkpoint, render, raw log는 commit하지
않는다. 그다음 현재 작업 branch를 게시한다.

```bash
scripts/sync_5090.sh publish lab
scripts/sync_5090.sh publish vigs
```

다른 branch 이름으로 게시하려면 `work/` 또는 `preserve/` 이름만 허용한다.

```bash
scripts/sync_5090.sh publish vigs work/colin/exp87-streaming-audit
```

스크립트는 다음 상황에서 중단한다.

- 추적 파일 또는 submodule이 dirty함
- detached HEAD임
- `main`으로 직접 게시하려 함
- 원격 branch를 덮으려면 force가 필요한 상태임

같은 branch에 양쪽 commit이 갈라졌다면 force하지 않는다. 새 보존 branch로 게시한다.

```bash
scripts/sync_5090.sh publish vigs preserve/wosas/exp87-diverged
```

## 로컬에서 검토하고 main 통합

통합은 한쪽, 기본적으로 로컬 워크스테이션에서만 수행한다.

```bash
scripts/sync_5090.sh fetch vigs
git -C /home/wosas/Desktop/26-1_RPM/gsProjects/VIGS-SLAM log --graph --oneline \
    main..colin-sync/work/colin/exp87-streaming-audit
git -C /home/wosas/Desktop/26-1_RPM/gsProjects/VIGS-SLAM switch main
git -C /home/wosas/Desktop/26-1_RPM/gsProjects/VIGS-SLAM merge --no-ff \
    colin-sync/work/colin/exp87-streaming-audit
```

테스트와 실험 기록을 확인한 뒤에만 bare hub의 `main`을 fast-forward한다.

```bash
git -C /home/wosas/Desktop/26-1_RPM/gsProjects/VIGS-SLAM push colin-sync main:main
```

`gs_floaterLab`도 같은 절차다. GitHub 반영은 이 과정과 별개이며 명시적으로 요청받았을
때만 `origin`/`custom`에 push한다.

## 대용량 결과 가져오기

5090 결과는 Git과 분리해 원격에서 로컬로만 가져온다.

```bash
scripts/sync_5090.sh pull-artifacts results/experiments/exp87
scripts/sync_5090.sh pull-artifacts context/experiments/exp87/evidence/runs
```

복사 위치는 다음과 같다.

```text
results/5090_mirror/results/experiments/exp87/
results/5090_mirror/context/experiments/exp87/evidence/runs/
```

이 명령에는 `--delete`가 없다. 원격 파일은 절대 변경하지 않는다. 같은 이름의 로컬
파일이 갱신되면 이전 파일은
`results/5090_mirror/.previous/<timestamp>/` 아래에 보존된다.

## 충돌·장애 시 원칙

1. `git push --force`, `git reset --hard`, `rsync --delete`를 사용하지 않는다.
2. push 거부는 손상 방지 장치다. 양쪽 branch를 먼저 `fetch`하고 비교한다.
3. 해결이 불명확하면 기존 branch를 수정하지 말고 `preserve/<machine>/<topic>`으로
   현재 commit을 먼저 게시한다.
4. 미커밋 파일은 Git hub에 존재하지 않는다. 장시간 작업은 작은 단위로 commit한다.
5. 실험 완료 시 `context/experiments` 카드, `INDEX.md`, `STATUS.md`를 함께 commit한다.
6. 5090 원본 output은 로컬 복사가 끝나도 자동 삭제하지 않는다.
