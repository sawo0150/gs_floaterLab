Causal Gradient-Balanced Update가 incremental mapping을 더 빠르게 하는가

Stage C의 random reshuffling 우세와 Stage D의 optimizer-aware alignment 결과를 실제 incremental mapping으로 연결하기 위한 후속 실험계획. 아직 검증되지 않았으며, 결과를 미리 결론으로 서술하지 않는다.

STATUS: PLANNED / NOT STARTED / LOCKBOX UNOPENED
검증할 핵심 가설: 미래 frame 전체를 미리 정렬하는 것이 아니라, 현재까지 도착한 frame을 대표하는 causal training anchor를 만들고, 짧은 microbatch의 평균 gradient가 그 anchor gradient를 근사하게 하면 batch-1 shuffle보다 동일 계산시간에서 더 안정적으로 수렴할 수 있다.

1. 이전 결과에서 무엇이 확인됐고 무엇이 아직 가설인가

확인됨 · Stage B전역 pure coverage membership은 temporal baseline보다 느렸다. 시간 quota 안의 representative 선택은 약한 AUC 이득만 보였다.
확인됨 · Stage C동일 view set에서 shuffle-without-replacement가 novelty-first, residual-first, alternating, replacement보다 빨랐다.
확인됨 · Stage D작은 held-out reference에 대한 −gRᵀΔθAdam은 현재 후보들의 one-step 개선 순위를 잘 예측했다.
아직 미확인여러 frame의 gradient를 섞거나 causal anchor에 matching한 microbatch가 실제 end-to-end AUC를 개선하는지는 실험하지 않았다.

따라서 Stage E는 “gradient alignment가 중요하다”를 반복 주장하는 실험이 아니라, 그 신호를 사용하지 않더라도 microbatch averaging 자체가 이득인지, 그리고 추가적인 gradient matching이 비용을 감수할 만큼 더 나은지를 단계적으로 분리한다.

2. 중요한 개념 정정 — gradient를 0으로 만드는 실험이 아니다

좋은 상쇄는 frame마다 다른 노이즈·편향 성분을 제거하면서 공통 descent 성분을 남기는 것이다.

g₁=(1,+5), g₂=(1,−5) ⇒ (g₁+g₂)/2=(1,0)

반대로 아래처럼 useful signal까지 상쇄하면 update가 사라진다.

g₁=(1,0), g₂=(−1,0) ⇒ (g₁+g₂)/2=(0,0)
따라서 목표: microbatch gradient norm을 최소화하는 것이 아니라, causal anchor가 가리키는 공통 방향을 보존하면서 개별 frame의 분산을 줄이는 것.

3. Causal 수학 모델

시점 t까지 도착해 scheduler가 합법적으로 사용할 수 있는 frame 집합을 다음처럼 둔다.

Aₜ = { frame i | arrival_time(i) ≤ t }

Aₜ에서 시간적으로 균형 잡힌 training anchor/replay buffer Rₜ를 유지한다. 최종 validation/lockbox와 미래 frame은 절대 포함하지 않는다.

g*ₜ = (1/|Rₜ|) Σᵣ∈Rₜ ∇θLᵣ(θₜ)

선택한 microbatch Bₜ의 평균 gradient는:

ḡ(Bₜ) = (1/|Bₜ|) Σᵥ∈Bₜ ∇θLᵥ(θₜ)

이상적인 gradient-matching 목적은 다음과 같다.

B*ₜ = argmin_B ‖ḡ(B) − g*ₜ‖² / measured_cost(B)

실제 Adam에서는 gradient 자체보다 현재 moment/preconditioner를 통과한 batch update의 anchor 방향 정렬도 함께 기록한다.

utility(B,t) = −g*ₜᵀΔθAdam(B) / cost(B)
해석: 하나의 anchor가 미래 전체 순서를 미리 정하는 것이 아니다. 현재 상태의 짧은 window 또는 microbatch만 평가하고, update 후 상태가 변하면 anchor와 score를 주기적으로 갱신하는 receding-horizon 문제다.

6. Stage E1 — One-step microbatch mechanism screen

기존과 비교 가능한 θ₀, 40초, 100초 snapshot에서 parameter와 Adam state를 저장하고, 각 arm의 microbatch로 실제 한 번 update한 뒤 별도의 curve-only audit loss 변화를 측정하고 정확히 원복한다.

중요: batch 선택에 쓰는 anchor는 training frame만 사용한다. curve-only audit은 결과 측정에만 사용한다.

고정 조건

  • 동일 Phase-1 checkpoint와 동일 representative candidate pool
  • RGB-only objective, densification/pruning 없음, 동일 parameter scope
  • 후보 UID 및 anchor UID/hash 고정·기록
  • 시점별·seed별 동일한 candidate group에서 paired counterfactual
  • 최소 3 seeds; 초기 개발은 aria1253, 일반화 결론은 추가 장면 전까지 금지

Admission과 order를 다시 섞지 않는 hard rule

  • 모든 E2 arm은 동일한 causal view-set admission 결과를 공유한다.
  • novelty/coverage는 admission에서만 사용할 수 있고, primary order score로 재사용하지 않는다.
  • order/microbatch 정책만 바꾸며 buffer 크기, frame UID, loss type을 동일하게 유지한다.
  • adaptive arm이 anchor refresh 때문에 처리 frame 수가 줄어드는 효과도 결과의 일부로 포함한다.

total_cost = admission + anchor_refresh + rejected_probes + chosen_update

한 번 계산한 선택 후보의 gradient가 실제 선택되면 Adam update에 재사용한다. 탈락 후보 backward는 추가비용으로 그대로 계산한다. Adam step 수뿐 아니라 processed frame-backward 수를 함께 기록한다.

30fps 스트림의 mapping compute rate는 E0에서 tracking deadline/headroom으로 정하고 main experiment 전에 고정한다. 품질 결과를 본 뒤 budget rate를 바꾸지 않는다.

11. 필수 로그와 leakage hard gate

  • 각 frame의 UID, timestamp, arrival time, admission time과 source hash
  • 각 시점의 available UID set hash와 미래 UID 접근 여부 assert
  • anchor UID/hash, candidate window UID, chosen/rejected UID
  • batch 구성, frame별 loss/gradient norm, pairwise cosine 또는 sketch
  • anchor refresh 비용, rejected probe 비용, chosen backward 재사용 여부
  • Adam step norm, LR/moment summary, non-finite 수
  • selection count, max age, stratum debt, causal queue 상태
  • E1 parameter/optimizer rollback 최대 오차와 checksum
즉시 실패 처리: scheduler가 curve-only/lockbox gradient를 사용함, 미래 frame metadata를 admission/order에 사용함, arm별 membership이 달라짐, adaptive 선택비용이 budget에서 누락됨, rollback 오차가 0이 아님.

12. 권장 구현 순서

  1. E1용 multi-view gradient accumulation과 exact rollback부터 구현한다.
  2. B1/B2/B4 random counterfactual로 batch averaging의 효과만 확인한다.
  3. 효과가 있을 때 temporal/spatial stratified B4를 추가한다.
  4. 그 후에만 training-anchor gradient matching oracle을 추가한다.
  5. E1 gate 통과 후 causal arrival/replay simulator와 budget credit ledger를 구현한다.
  6. E2-RR-B1/B4를 먼저 완료하고, adaptive Match-B4는 마지막에 추가한다.
최종 판단 원칙: Stage E의 목적은 복잡한 scheduler를 정당화하는 것이 아니다. 가장 싼 RR-B4 또는 stratified-B4가 충분하면 그것을 선택하고, gradient matching은 selection overhead를 포함해서도 명확한 AUC 이득이 있을 때만 채택한다.
