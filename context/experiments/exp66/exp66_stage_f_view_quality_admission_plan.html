2. 큰 motion과 나쁜 frame을 구분해야 한다

카메라 이동량이나 optical-flow magnitude가 크다는 이유만으로 frame을 제거하면 안 된다. 큰 motion은 다음을 의미할 수 있다.

  • 새로운 surface와 시점을 빠르게 확보한 유용한 frame
  • 정상적으로 sharp하지만 frame 간 baseline이 큰 frame
  • 실제로 motion blur 또는 rolling-shutter 왜곡이 있는 frame
  • tracking이 실패해 pose가 부정확한 frame

따라서 motion magnitude는 quality score가 아니라 위험·조건 변수로 기록한다. 실제 rejection은 sharpness, exposure, pose confidence처럼 관측 신뢰도를 나타내는 별도 증거로 결정한다.

large motion ≠ blur ≠ bad pose ≠ low utility
금지할 shortcut: flow/pose displacement가 큰 상위 x%를 그대로 제거하거나, residual이 큰 frame을 저품질로 정의하는 것. 이는 novel/hard view를 체계적으로 삭제할 수 있다.

Temporal-relative sharpness

절대 Laplacian 값은 장면 texture에 크게 의존하므로, 인접 시간창의 median에 대해 상대화한 점수를 함께 사용한다.

qsharp(v) = sharpness(v) / [ε + median{sharpness(u): |tᵤ−tᵥ|≤W}]

이렇게 하면 textureless 구간 전체를 저품질로 버리는 오류를 줄일 수 있다. 단, metric이 실제 blur를 측정하는지는 Stage F0에서 별도로 검증한다.

Combined score

각 metric을 temporal bin 안에서 percentile [0,1]로 정규화하고, 임의 weight tuning을 피하기 위해 equal-weight geometric mean을 먼저 사용한다.

qcombined(v) = [qsharp(v) · qexposure(v) · qpose(v)]^(1/3)

한 항이 매우 낮으면 전체 점수가 낮아져 명백한 corruption을 억제하지만, 어떤 항이 원인인지 manifest에 별도로 남긴다. Motion magnitude는 이 식에 직접 넣지 않는다.

Hard reject와 soft preference 분리

  • Hard reject: decode failure, invalid/missing pose, 거의 전체 clipping처럼 명백히 학습 불가능한 frame만.
  • Soft preference: blur 의심, pose confidence 저하, contrast 부족은 bin 내부 ranking으로만 사용.
  • 선택 수가 부족하면 같은 temporal bin의 다음 후보로 채워 temporal quota를 보존한다.

10.3 Dense frame의 causal eligibility와 admission 시점

RGB pixel은 frame이 도착하면 볼 수 있지만, dense frame의 학습 pose는 곧바로 준비되지 않는다. 현재 구현은 왼쪽·오른쪽 keyframe이 모두 도착한 뒤 그 사이 pose를 완성한다.

tready(v) = max[trgb(v), tright-KF(v), tpose-fill-done(v)]
A(t) = {v | tready(v) ≤ t, eval(v)=false, hard-invalid(v)=false}
  • Sharpness·exposure처럼 image-only feature는 trgb에 계산·cache할 수 있다.
  • Pose 관련 feature와 최종 admission은 tready 전에는 사용할 수 없다.
  • causal_pose_residual은 보간 pose와 trajectory-filler pose의 차이일 뿐 calibrated confidence가 아니다. F0 검증 전에는 hard reject에 쓰지 않는다.
  • 현재 코드에 dense frame별 inlier ratio/covariance가 직접 보존되지 않으므로, 신뢰할 pose score가 확보되지 않으면 F1-Pose와 EF의 pose 항을 생략한다. 임의 proxy로 채우지 않는다.

10.4 Online temporal quota — 미래를 보지 않고 동일 cardinality 유지

F1의 “전체 sequence에서 가장 좋은 784장”을 그대로 옮기면 미래 누출이다. EF-C에서는 sensor-time 1초 bin을 닫은 뒤, 그 bin에 이미 도착했고 pose까지 준비된 후보만 비교한다. 목표 rate r은 F1 전에 고정하며 D12를 채택하면 1초당 최대 12장을 admission한다.

tclose(b) = 첫 arrived keyframe k 중 sensor-time(k) > tb,end 인 시점
q(b) = min[round(r · Δtb), |A(tclose(b)) ∩ bin b|]
  • Temporal arm: 닫힌 bin 안에서 균일한 시간 위치의 q(b)장을 선택한다.
  • Quality arm: 같은 닫힌 bin·같은 q(b) 안에서 사전 고정 quality score가 높은 frame을 선택한다.
  • 두 arm 모두 같은 bin-close/pose-ready 지연을 적용해 quality arm만 미래를 더 보는 일이 없게 한다.
  • 한번 학습에 사용한 frame을 나중에 더 좋은 frame이 왔다고 소급 교체하지 않는다.
  • stream 끝까지 오른쪽 keyframe이 생기지 않은 마지막 open bin/interval은 tail에서 보충하지 않고 모든 arm에서 제외한다.
  • Regular tracked keyframe은 primary EF-C에서 quality admission으로 제거하지 않는다. 그러면 tracking graph와 Gaussian birth 자체가 달라져 F의 membership 효과를 분리할 수 없기 때문이다.
  • 다만 학습 가능한 keyframe과 admitted dense frame은 모두 map()의 공동 candidate pool에 들어간다. Stage E scheduler가 각 map iteration의 제한된 학습 slot을 두 종류 사이에 배분한다.

정책은 map()이 세 stack을 만든 직후, current_viewpoints를 확정하기 전에 삽입한다. Tracking/keyframe membership과 Gaussian birth 자체는 유지하되, 각 optimizer step이 실제로 render/backward할 batch Bt의 dense:keyframe 구성과 순서를 결정한다. 새 frontier keyframe starvation을 막기 위해 사전 고정한 최소 frontier slot을 두고, 나머지 slot만 historical keyframe과 dense frame 사이에 배분한다.

현재 map()은 선택된 view loss를 평균이 아니라 합산한다. 따라서 primary 비교는 모든 arm·모든 paired 시점에서 동일한 총 view slot 수를 사용하고, 후보가 부족하면 같은 arm 공통 규칙으로 keyframe을 채운다. Batch cardinality 자체를 바꾸는 별도 B1/B2/B4 진단은 loss mean 또는 LR 보정을 사용해야 하며, 두 비교를 섞지 않는다.

기존 Stage E2가 background_polish_step() 기반으로 구현된다면 최종 경로로 사용하지 않는다. E1에서 얻은 원리는 map() 공동 scheduler로 다시 구현·검증하며, E와 F가 같은 native map() run 안에서 위 2×2로 비교되는 EF-C가 최종 acceptance다.

Background hard gate: EF-C의 모든 arm은 background_polish_step() 호출 수=0, background optimizer step=0이어야 한다. Dense frame이 polish_viewpoints라는 legacy container에 저장되는 것은 허용하지만, 그 container를 background worker가 학습에 사용하는 것은 금지한다.
Winner gate: F1 winner가 없으면 EF-C-F/EF를 만들지 않고 Temporal admission을 유지한다. E1에서 공동 batch 구성에 유효한 원리가 없으면 Map-E를 만들지 않고 Map-RR을 유지한다. Offline에서 실패한 복잡한 정책을 incremental이라는 이유로 다시 넣지 않는다.

10.7 Budget, zero-tail, curve 측정

Ctotal(T) = Ctrack + Cpose-ready + Cquality + Cmap-schedule + Crender/backward/map-step
Primary budget입력 시작부터 마지막 sensor timestamp까지의 실제 wall time과 mapping duty cycle. Quality/gradient probe도 포함한다.
Strict deadlinerecording duration의 1.5배 이내. 이는 30fps 검증이 아니라 현재 프로젝트의 1.5× live-budget 계약이다. GPU별 가능한 update 수 차이도 결과다.
Zero-tail마지막 RGB 도착 뒤 optimizer step 0회. queue drain이 update를 실행했다면 실패로 기록한다.
Fairness같은 input replay, evaluator exclusion, map iteration 수, step당 총 view slot, admission rate, seed pairing. Arm별 dense/keyframe backward 수를 함께 기록한다.

중간 AUC를 얻기 위해 live loop 안에서 held-out rendering을 끼워 넣지 않는다. 그것은 scheduler의 idle budget을 빼앗는다. 사전에 고정한 sensor-time prefix에서 별도 replay를 종료하고 zero-tail map을 offline metric-only로 평가한다. EF-C1에서는 prefix 길이에 따라 *_frac 경계가 다시 계산되는 구현을 금지하고, 같은 unknown-horizon online policy state를 그대로 사용한다.

AUCstream = ∫ MSEheld-out(t) dt / (Tend − Tstart)

10.9 구현 전에 필요한 최소 변경

  1. RGB ingest 시 image-only quality를 CPU에서 계산하는 causal feature cache와 timing log.
  2. 오른쪽 keyframe/trajectory-filler 완료 뒤 pose_ready 이벤트를 내는 dense record.
  3. 1초 bin close 후 동일 quota를 확정하는 online admission buffer. 미래 UID manifest 사용 금지.
  4. register_causal_dense_views()에 quality/reason/admission timestamp metadata 전달.
  5. map()의 세 candidate stack 조립부를 명시적인 MapViewScheduler interface로 분리하고, frontier minimum + shared historical slots를 반환하게 한다.
  6. 모든 arm에서 map iteration 수와 총 view slot 수를 고정한다. Slot 수를 바꾸는 진단은 loss mean/LR 보정을 별도 hard gate로 둔다.
  7. background_polish_step()을 완전히 비활성화하고 호출·optimizer-step counter가 0이 아니면 run을 실패시킨다.
  8. optimizer step마다 wall timestamp와 선택 batch UID/type을 남겨 last sensor arrival 이후 update가 0인지 자동 검사. 현재 demo.py의 종료부는 _gs_queue.join()으로 pending mapping packet을 drain하므로, 이 구간에서 실제 optimizer step이 생기는지도 별도 계측하고 생기면 strict 실패로 처리한다.
  9. EF-C1 전에는 전체 --length 비율 schedule을 online observable 기반 schedule로 교체하고 baseline 자체를 세 장면에서 먼저 재검증.

  • optimizer-step wall timestamp, last-sensor-arrival timestamp, post-tail update count
  • prefix별 keyframe/Gaussian birth·densify·prune 수, queue backlog, deadline miss
  • map iteration별 candidate keyframe/dense 수, selected UID/type, frontier/history 구분, 총 slot 수, selection debt와 scheduler score
  • background_polish_step call/optimizer-step count(둘 다 반드시 0)
즉시 실패 처리: arm별 cardinality·temporal quota가 다름, 의도하지 않았는데 map step/view slot 수가 다름, quality를 order score에도 재사용함, held-out 결과로 threshold를 조정함, motion magnitude만으로 hard reject함, selected set이 eval/lockbox와 overlap함, pose-ready 전 사용함, 미래 UID/전체 sequence 통계를 읽음, background_polish_step()이 한 번이라도 실행됨, 마지막 sensor frame 뒤 optimizer update가 발생함.

13. 권장 구현 순서

  1. Quality feature extractor와 JSONL audit만 구현한다. 학습 코드는 아직 바꾸지 않는다.
  2. F0 synthetic corruption과 natural contact sheet로 metric을 검증한다.
  3. Temporal baseline과 RandomDrop control을 생성한다.
  4. Sharp/Pose/Exposure 단일축 manifest를 각각 생성해 F1을 수행한다.
  5. 단일축 결과를 보기 전에 고정한 equal-weight Combined manifest를 함께 생성한다.
  6. F1 gate를 통과한 축만 representative 2×2 및 density interaction으로 확장한다.
  7. E1/F1 winner를 고정한 뒤 native VIGS 경로에 causal feature cache·pose-ready·bin-close admission과 map() 공동 view scheduler를 구현한다.
  8. aria1253에서 EF-C0 2×2를 수행해 성장 map interaction과 system cost를 검증한다.
  9. 전체 길이 비율 schedule을 제거한 scene-independent baseline을 먼저 검증한 뒤, threshold를 다시 조정하지 않고 최소 세 장면 EF-C1을 수행한다.
  10. EF-C1까지 통과한 조합만 실제 Aria live integration 후보로 승격한다.
