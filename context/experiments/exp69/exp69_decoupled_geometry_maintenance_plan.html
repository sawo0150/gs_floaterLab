4. Generic mature dust GC의 수학적 정의

Gaussian g마다 전체 frame 나이가 아니라 실제 optimizer service 기준 상태를 유지한다.

a_g(t) = g가 생성된 뒤 받은 optimizer opportunity 수 alpha_bar_g(t) = EMA(opacity_g) c_bar_g(t) = EMA(actual render contribution_g) k_g(t) = low-opacity AND low-contribution가 연속 유지된 audit 횟수

기본 candidate는 다음과 같다.

Q_t = { g | a_g ≥ a_min AND alpha_bar_g ≤ tau_alpha AND c_bar_g ≤ tau_contrib AND k_g ≥ k_min AND NOT quarantined_newborn(g) }
  • Age: 새 Gaussian이 몇 번 보기도 전에 삭제되는 것을 막는다.
  • Opacity EMA: 한 step의 순간적인 감소가 아니라 지속적 투명화를 본다.
  • Contribution EMA: 낮은 opacity Gaussian 여러 개가 실제 이미지를 함께 설명하는 경우를 보호한다.
  • Persistence: frame 번호가 아니라 독립 audit/service 기회 수로 성숙도를 표현한다.

삭제 순서는 예상 시각 손실이 작은 후보부터이며, 한 event에서 제거할 수 있는 총 기여량을 제한한다.

h_g = c_bar_g + lambda_s · terminal_support_g P_t = smallest-harm prefix of Q_t subject to: sum_(g in P_t) c_bar_g ≤ B_visual(t) estimated_prune_ms(P_t) ≤ B_time(t)

opacity<.1 즉시 삭제는 금지한다. exp68의 .1은 분석 band이지 안전한 hard-prune threshold가 아니다. threshold와 persistence는 baseline telemetry 분포를 먼저 보고, method 결과를 보기 전에 공통값으로 pre-register한다.

5. Render contribution은 어떻게 측정할 것인가

가장 좋은 신호는 각 Gaussian이 최종 pixel color에 실제로 남긴 alpha-transmittance mass다.

c_g(v) = sum_p T_{g,p}(v) · alpha_{g,p}(v) c_bar_g ← (1-rho)c_bar_g + rho · c_g(v)
후보 신호장점한계판정
Raster alpha×transmittance mass실제 pixel 기여와 가장 직접적kernel 계측 추가 필요우선 목표
Opacity×projected area×visibility기존 tensor로 근사 가능occlusion과 중복 설명을 과대평가초기 proxy
Gradient norm현재 loss 민감도 반영이미 잘 맞은 유효 Gaussian도 작을 수 있음단독 사용 금지
n_touchedraster 접촉량을 싸게 관측Fisher/Hessian이나 per-Gaussian 기여가 아님hard-prune 근거로 해석 금지

Kernel 계측 전에는 proxy를 바로 action에 쓰지 않고, 저장된 view buffer에서 offline exact contribution과의 rank correlation을 먼저 측정한다.

6. O(N²)을 피하는 증분 candidate 관리

매 map step 전체 Gaussian의 opacity와 contribution을 CPU로 가져오면 긴 stream에서 다시 누적 O(N²)이 된다. stable ID 기반의 변경 집합과 회전 audit를 사용한다.

  • 매 step 갱신 대상은 현재 view에서 실제로 touched된 ID와 carve/opacity action을 받은 ID의 합집합이다.
  • 오래 보이지 않은 row가 영원히 누락되지 않도록 stable-ID ring cursor로 작은 audit chunk를 순회한다.
  • Candidate queue는 array index가 아니라 stable ID를 저장한다. Prune compaction 뒤 ID→row mapping만 갱신한다.
  • 동일 ID 중복 enqueue를 막고, opacity가 회복되면 queue에서 lazy invalidation한다.
  • 한 event의 mask 생성과 optimizer compaction 비용을 실측하여 batch capacity를 조절한다.
per-step cost ≈ O(|visible IDs| + |action IDs| + audit_chunk) full audit cycle = O(N), amortized across many service events

7. “더 자주 prune”의 정확한 실행 clock

Full densify_and_prune()를 더 자주 호출하지 않는다. Native densification 통계와 topology cadence는 그대로 두고, maybe_mature_dust_gc()를 optimizer step 뒤 torch.no_grad() 구간에 별도로 둔다.

run_gc(t) = candidate_debt(t) > 0 AND estimated_gc_ms ≤ available_maintenance_ms(t) AND no topology/pose-revision transaction is active

고정 frame interval 대신 두 budget을 동시에 사용한다.

  1. Visual budget: 한 event와 전체 stream에서 제거 가능한 누적 render contribution 상한.
  2. Time budget: 최근 prune batch의 ms/row EMA로 strict service horizon 안에서 처리 가능한 row 수 계산.
K_gc(t) = floor(B_time(t) / EMA(ms_per_pruned_row))

두 가지 평가를 분리한다. service-matched 실험은 exp67과 photometric step 수를 같게 하고 GC의 순수 품질 영향을 본다. deadline-matched 실험은 strict 1.5× 안에서 실제 배포 가능성을 본다. 둘을 한 숫자로 섞지 않는다.

11. 실험 순서

P0
exp67 기준선 무결성 재현

세 장면의 PSNR·step 수·strict time·PLY opacity band를 다시 고정한다. 이후 threshold를 바꾸지 않는다.

A
GC telemetry-only

opacity/contribution/age 분포와 candidate queue 성장, 예상 삭제량, ms/row를 측정한다. 실제 Gaussian은 삭제하지 않는다.

B
Offline counterfactual prune

저장된 PLY에서 후보를 가상 삭제한 뒤 동일 trajectory를 render하여 PSNR harm, vertex/memory 절감, footprint 변화를 측정한다.

C
Online GC · service-matched

exp67과 photometric update 수를 동일하게 맞추고 wall time은 별도 기록한다. GC 자체의 품질 인과만 검증한다.

D
Online GC · strict deadline-matched

동일 공통 설정으로 strict 1.5×에 넣어 유지 가능한 batch capacity와 장기 dust debt를 확인한다.

E
Carve telemetry → reversible action

GC champion을 고정하고 detector-only, counterfactual, soft action을 순서대로 한 축씩 추가한다.

F
Bounded archive 독립 재검증

Geometry champion을 고정한 뒤 exp67 membership과 bounded archive만 비교한다.

G
최종 blind universal validation

1253·305·12F, 동일 설정, 반복 run. 1253/305 label은 설정 선택이 끝난 뒤에만 연다.

13. 평가 지표와 PASS 규칙

13.1 Photometric

  • Fixed held-out PSNR/SSIM/LPIPS와 convergence AUC.
  • Service-matched에서는 photometric optimizer step 수와 source mix를 정확히 맞춘다.
  • 1253/305의 27 dB는 충분한 절대 floor이지만, 그것만으로 큰 하락을 허용하지 않는다.

15. 실패 모드와 중단 조건

  1. Holes/PSNR 급락: contribution proxy가 실제 중요도를 대변하지 못한 것. Action을 중단하고 telemetry/offline correlation으로 복귀.
  2. Dust count만 감소하고 area 유지: 작은 dust 대신 giant splat이 남거나 커진 것. scale/footprint gate 재검토.
  3. 12F step 감소: GC maintenance가 photometric service를 침범한 것. batch를 숫자로 튜닝하기 전에 계측/자료구조를 수정.
  4. Candidate debt 무한 증가: strict budget에서 방법 자체가 감당 불가. offline 후처리로 숨기지 않고 online FAIL 처리.
  5. Newest surface 삭제: age/service clock 또는 stable-ID reconciliation 버그. 즉시 중단하고 unit test 보강.
  6. 한 scene만 성공: scene별 threshold를 만들지 않는다. 신호 정의 또는 proxy를 다시 설계.
