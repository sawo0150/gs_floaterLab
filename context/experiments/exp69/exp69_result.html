1. 결론부터

v5 명명 업데이트: 이 문서의 1–14장은 mature-dust와 v1–v4 scheduler의 성공·실패 이력을 그대로 보존한다. 이후 exact world-Jacobian PGBA를 결합한 현재 구성을 v5로 명명했다. 이는 1253/305용 현재 scheduler 채택을 뜻하며, geometry action의 3-scene universal PASS를 새로 주장하는 것은 아니다. 12F의 빠른-motion 한계도 별도 제한사항으로 남긴다.
성공한 부분: n_touched를 Fisher/기여도로 잘못 해석하지 않고, 실제 alpha compositing에서 Gaussian별 T_before × alpha를 직접 누적하는 저비용 계측 경로를 만들었다. stable ID 상태, EMA, 성숙도, lifetime visual-risk budget, topology 변화 후 상태 정합까지 map() 내부에서 동작한다.
조건부로 유망한 부분: 매우 보수적인 reversible suppression은 1253에서 27.28 dB를 유지하며 nominal high-opacity floater를 154→143으로 줄였다. 12F는 26.22 dB로 기존 exp67 반복 범위 하단과 거의 맞닿았지만, 305 한 번의 strict run은 25.87 dB로 크게 실패했다. 비동기 trajectory 변동이 섞였으므로 원인을 suppression 하나로 단정할 수 없지만, 현재 증거만으로 범용 PASS라고 부를 수도 없다.
기각한 부분: hard prune은 보수적 조건에서도 12F를 25.90 dB로 낮췄다. bounded archive는 1253/305 PSNR을 27.89/29.42 dB로 올렸지만 giant-splat/global footprint를 크게 악화시켰다. 따라서 둘 다 production default로 채택하지 않는다.

즉 exp69는 “floater 제거까지 완료된 champion”이 아니라, 검출기는 성숙했고 action의 위험 경계가 드러난 실험이다. 실패 결과를 숨기거나 장면별 threshold를 따로 맞추지 않았다.

2. 고정한 문제와 PASS 규칙

  • 입력은 aria RGB/IMU의 실제 순서를 유지한 strict 1.5× causal streaming이다.
  • 정책 삽입점은 GSBackEnd.map() 내부다. background_polish_step은 사용하지 않는다.
  • 1253, 305, 12F에 동일한 설정을 쓴다. dataset 경로 외 scene/frame별 예외는 없다.
  • view membership과 optimizer order는 exp67의 dense admission + shuffle-without-replacement를 고정한다.
  • 1253/305 photometric floor는 사용자가 완화한 27 dB, 12F는 exp67 반복 평균 약 26.41 dB에 대한 scene-relative non-inferiority로 본다.
  • geometry는 한 개 count가 아니라 opacity band, manual-region high-opacity/support, covariance footprint/area를 함께 본다.
  • 라벨은 사후 평가에만 쓴다. detector와 threshold 선택에는 사용하지 않았다.

주의: strict pipeline은 tracking과 mapping이 비동기로 함께 돌아가므로 run마다 keyframe/PGBA pose revision 수가 달라질 수 있다. 단일 run의 PSNR 차이 전체를 geometry action의 인과효과로 읽지 않는다.

3.1 정확한 render contribution

pixel p에서 Gaussian g의 compositing mass:  c_gp = T_before(g,p) · alpha(g,p)
view v에서의 정규화 기여도:             m_g(v) = (1 / HW) Σ_p c_gp
전체 render alpha mass:                 A(v) = (1 / HW) Σ_p [1 - T_final(p)]

CUDA rasterizer는 audit 때만, 그리고 현재 opacity≤0.03인 Gaussian에 대해서만 atomic accumulation을 수행한다. 전체 alpha denominator는 추가 per-Gaussian atomic 없이 최종 transmittance로 계산한다. 예전 구현처럼 “dust subset의 mass”를 denominator로 쓰면 0.1% budget이 사실상 dust의 0.1%가 되어 지나치게 빨리 소진되므로 이를 수정했다.

3.2 범용 성숙 조건

eligible(g) = observed
  ∧ opportunities(g) ≥ 10
  ∧ consecutive_low_persistence(g) ≥ 5
  ∧ current_opacity(g), EMA_opacity(g) ≤ 0.005
  ∧ EMA_exact_contribution(g) ≤ 3×10⁻⁶
  ∧ EMA_opacity_footprint(g) ≤ 3×10⁻⁶

EMA decay는 0.90이다. 서로 다른 view에서 적어도 10번 관측되고, 그중 마지막 5회 연속으로 모든 low 조건을 만족해야 한다. 한 프레임에서 우연히 가려졌다는 이유만으로 삭제하지 않기 위한 probation이다.

3.3 action과 위험 예산

lifetime visual spend = Σ selected_g EMA[m_g] / EMA[A]
constraint            = lifetime visual spend ≤ 3×10⁻⁴  (0.03%)
batch cap              = 512 rows / action event
reversible action      = opacity ← 0.25 · opacity
hard action            = Gaussian + Adam state를 prune_points()로 제거

action은 256 optimizer actions마다만 실행해 O(N) compaction을 amortize한다. “pruning을 더 자주”는 후보가 정확하다는 보장이 생기기 전에는 손실을 키울 수 있으므로, audit 빈도와 destructive action 빈도를 분리했다.

3.4 증분 topology와 실패 안전성

  • Gaussian의 row index가 densify/prune으로 바뀌어도 point_ids로 history를 보존한다.
  • append-only birth는 fast path, 실제 compaction 때만 O(N) ID reconciliation을 수행한다. 매 step 전 Gaussian을 다시 훑는 O(N²) 누적을 피한다.
  • GS worker packet은 모든 branch에서 6-field schema로 통일했다. 과거 5/6 tuple 불일치로 worker가 죽고 queue join이 영원히 대기하던 문제를 수정했다.
  • worker 예외는 GS_WORKER_FATAL로 기록하고 task_done()을 보장해 fail-fast한다.

10. 무엇을 production에 남길 것인가

  1. 기본 scheduler: exp67의 unbounded dense admission + shuffle을 유지한다. novelty-first로 바꾸지 않는다.
  2. 진단: exp69 exact telemetry를 켤 수 있게 유지한다. 8-step audit는 CPU 누적 시간이 전체 run에서 약 0.6–2.0초 수준이었다.
  3. reversible suppression: 실험 flag로만 보존한다. 3-scene 반복/고정-trajectory 검증 전 기본값으로 승격하지 않는다.
  4. hard prune: off. 최종 기여도가 작아도 학습 중 제거하면 이후 gradient 경로를 잃는다.
  5. bounded archive: off. 현재 capacity law는 small active set을 보장하지 않고 geometry 반례가 있다.
  6. carve: exp69에서 재도입하지 않았다. low-opacity dust와 3D free-space violation은 서로 다른 detector 문제이므로, dust action이 실패한 상태에서 둘을 다시 섞으면 인과가 불명확해진다.
다음에 가장 먼저 필요한 실험: 동일 tracking trajectory/동일 view service를 저장해 두고 telemetry와 suppression을 replay하는 paired protocol이다. 이것으로 305의 25.87 dB가 geometry action 때문인지, 3회 대 6회의 pose revision 등 비동기 tracking 차이 때문인지 분리해야 한다. 그 전에는 threshold를 더 미세 조정하지 않는다.

13. 추가 검증 — 고정 크기 FIFO epoch sampler (B48–B50)

질문: 전체 causal pool을 계속 커지는 한 epoch으로 도는 대신, GPU가 실제로 완료한 optimizer draw를 clock으로 삼아 크기 K의 epoch을 만들고 그중 비율 ρ를 새 causal view에 예약하면 장기 stream에서도 일정한 replay 주기와 무작위성을 함께 유지할 수 있는가?

13.1 구현한 규칙

epoch membership size:              K
new-view slots per completed epoch: q = round(K · ρ)
mature-view weight:                 w_i = w_floor + w_bonus exp(-n_i / τ)

검증 설정: K=50, ρ=0.08 → q=4, w_floor=1, w_bonus=1, τ=2
physical dense-camera FIFO capacity: 500
  • --mapping_replay_epoch_size와 --mapping_replay_new_fraction은 독립 CLI parameter다. 실험 wrapper에서도 EXP69_FIFO_EPOCH_SIZE, EXP69_FIFO_NEW_FRACTION으로 덮어쓸 수 있다. 50과 0.08은 B48–B50 recipe의 기본값이지 scheduler 내부의 frame/scene switch가 아니다.
  • 매 K개의 실제 완료 replay draw가 다음 admission quota q를 만든다. 미래 frame에 과거 compute credit을 미리 쓰지 않는다.
  • 신규 후보는 도착한 keyframe interval 사이에서 temporal maximin으로 membership만 고른다. 나머지 membership은 FIFO live pool에서 위 floor-exponential weight로 without-replacement 추출하고, 최종 50장은 전부 한 번 더 무작위 shuffle한다. novelty는 optimizer 순서를 정하지 않는다.
  • DROID keyframe replacement 때문에 서로 겹치는 interval이 같은 RGB frame을 다시 내놓을 수 있어, controller 전역 candidate-ID deduplication을 추가했다. 수정 전 실측 신규 비율 6.09%가 수정 후 7.83–8.00%로 회복됐고 skipped_dense도 정상 구간에서 0이 됐다.
  • dense camera는 sensor-time FIFO 500장으로 제한한다. queue의 lifetime count도 퇴출 시 함께 제거한다.

14. 추가 검증 — pose-balanced active + unbounded archive

질문: FIFO처럼 과거 view를 버리지 않으면서도, 계속 커지는 전체 pool의 한 epoch에 admission이 묶이는 문제를 피할 수 있는가? 이를 위해 새 frontier의 pose 대표 view는 active, 나머지 causal view는 무제한 archive에 보존하고 두 pool을 각각 shuffle-without-replacement로 학습하는 정책을 시험했다.

14.1 구현한 수학적 규칙

active membership:
  현재 keyframe window와 맞닿은 interval마다 pose-farthest 대표 view 1장

pose distance:
  d(i,j) = sqrt((||t_i-t_j|| / median Δt_KF)^2
              + (SO(3)(R_i,R_j) / median ΔR_KF)^2)

active demand:
  D_A = median(d_active-to-archive) / (1 + median(d_active-to-archive))
        · (1 + mean Fisher-cosine novelty),       0 ≤ D_A ≤ 2

pool choice:
  odds(active) = |A| / |H| · (1 + D_A)
  P(active) = odds(active) / (1 + odds(active))
  • archive는 무제한이라 FIFO forgetting이 없다. active/archive partition은 working membership일 뿐 전체 causal training set을 삭제하거나 줄이지 않는다.
  • active 크기는 frame 수가 아니라 live frontier interval 수로 정한다. 그 안에서는 위치와 회전을 현재 keyframe의 median motion으로 정규화한 farthest-point selection을 쓴다. 장면별 거리 threshold는 없다.
  • Fisher cosine은 membership의 tie-break와 active service demand에만 사용한다. optimizer 순서를 novelty-first로 정하지 않으며, 각 pool 내부 순서는 random shuffle이다.
  • 별도 historical demand D_H는 두지 않았다. active demand가 0이면 active draw 확률은 정확히 population fraction이 되어 full-pool random sampling의 주변분포를 복원한다. demand가 커져도 active odds 배수는 최대 3배라 frontier 독점을 막는다.
  • 정책 삽입점은 GSBackEnd.map() 내부이고 background_polish_step은 사용하지 않는다. dense admission, loss, terminal GC, strict 1.5× 조건은 기존 terminal_gc_sparse_moments와 동일하다.

15. v5 — exact-PGBA adaptive scheduler

기존 VIGS 경로는 PGBA 뒤 Gaussian 중심은 world-frame 선형변환으로 옮기면서도, anisotropic orientation에는 lietorch pose quaternion을 Gaussian quaternion에 직접 곱했다. 여기에는 두 문제가 있었다. GaussianModel/renderer는 wxyz, lietorch는 xyzw 순서를 쓰며, 단순 inverse camera delta도 일반적인 비가환 회전에서는 중심에 실제 적용된 R_now R_prev^T와 같지 않다.

x' = C_now + R_delta (x - C_prev) / s
q' = q_wxyz(R_delta) ⊗ q

R_delta는 xyz update가 반환한 동일한 3×3 world Jacobian을 재사용한다.

수정 경로는 회전행렬을 180° 부근에서도 안정적인 largest-component 방식으로 unit wxyz quaternion으로 바꾸고, raw quaternion Adam 1차 moment에는 같은 left-product Jacobian을, diagonal 2차 moment에는 그 원소별 제곱 근사를 적용한다. 따라서 중심, 공분산 축, optimizer state가 하나의 좌표변환을 따른다.

16.5 terminal dust 조건 완화 sweep

기존 terminal GC는 online destructive action용으로 만든 opacity≤0.005 + opportunity≥10 + persistence≥5 + opacity EMA + 두 contribution threshold를 마지막 순간에도 그대로 사용했다. 그 결과 terminal 직전 opacity≤0.1 row 18,465/26,247개 중 실제 삭제는 1253 147개, 305 2,985개뿐이었다. 단순 opacity band 전체를 dust라고 부르는 것은 부정확하지만, terminal-only action에는 이 certificate가 지나치게 보수적인지 별도 counterfactual sweep으로 검사했다.

simple terminal candidate:
  observed ∧ opportunities ≥ 3 ∧ opacity ≤ tau_opacity
  ∧ max(exact contribution EMA, opacity-footprint EMA) ≤ tau_score

selected candidates are ordered by importance and clipped by:
  sum(selected exact contribution) / full render alpha ≤ 0.003

17. 최종 v6 — carve main-effect sweep + 실제 terminal pruning

재정의: 사용자와 합의한 대로 v6는 더 이상 section 16의 단일 λ=0.02 run이 아니다. v5 + visible-lazy carve + sweep으로 고른 공통 carve 강도 + sweep으로 고른 terminal hard-prune 전체를 뜻한다.

17.1 최종 구조

v6 = v5 scheduler / exact PGBA
   + arrived-depth causal carve field
   + visible-lazy stale refresh
   + soft opacity gradient: lambda = 0.01
   + reversible opacity prox: lifetime budget = 0.005
   + stream-end terminal cleanup:
       observed
       ∧ distinct opportunities ≥ 3
       ∧ current opacity ≤ 0.03
       ∧ touch EMA ≤ 3e-5
       ∧ footprint EMA ≤ 3e-5
       ∧ cumulative contribution / full render alpha ≤ 0.003

disabled:
  online dust deletion / xyz carve force / hard carve prune
  newborn gate / scene-specific parameter / post-stream training

terminal policy는 online optimization 도중에는 Gaussian을 지우지 않는다. strict stream과 map worker가 모두 끝난 뒤, 세 개 이상의 서로 다른 view에서 실제로 관측됐지만 현재 opacity와 lifetime render importance가 모두 낮은 row만 importance 오름차순으로 한 번 hard-prune한다. 따라서 낮은 opacity 하나만 보고 지우는 규칙은 아니다.

19. v7 — multi-view verified carve ray와 adaptive surface margin

질문: 기존 v6의 균일 grid depth ray와 0.20 m surface 보호대를 그대로 쓰면, 실제로 여러 keyframe에서 확인된 ray를 충분히 활용하지 못하고 surface 근처 floater를 free-space로 판정하지 못할 수 있다. v7은 이 지점만 바꾸고 v5 scheduler, v6의 λ=0.01·opacity budget·terminal cleanup은 그대로 고정했다.

19.1 최종 구현

ConvGRU + BA가 갱신한 metric depth
  → 기존 VIGS depth_filter로 causal 이웃 keyframe reprojection 확인
  → support ≥ 2인 pixel만 후보
  → image grid별 최고 support ray를 골라 keyframe당 최대 64개
  → support = 2: surface margin 0.10 m
     support ≥ 3: surface margin 0.05 m
  → arrived-only global 3D carve field에 누적

따라서 이것은 dense RGB frame에 붙는 2D depth loss가 아니다. keyframe에서 이미 SLAM이 계산한 depth와 pose를 이용해 3D free-space evidence를 만들고, 어떤 RGB view가 replay되든 map() 내부의 global opacity regularizer가 그 evidence를 사용한다. 64개는 장면별 값이 아니라 1253/305/12F/1253_rot에 동일하게 적용한 strict-budget 상한이다.

19.2 O(history) spike를 제거한 방식

  • verification cache + batch 8: 같은 keyframe을 매 mapping packet마다 다시 depth_filter하지 않는다. 새 keyframe 8개를 한 번의 CUDA call로 묶고, 아직 batch에 들어가지 않은 keyframe은 support=0으로 보내 carve 관측만 지연한다.
  • PGBA lazy rebuild: PGBA는 action budget을 환불하지 않은 채 pose-dependent voxel field만 비운다. corrected ray endpoint는 compact queue에 넣고 이후 map() 호출마다 최대 512 ray씩 복구한다. 전체 과거 keyframe을 한 번에 다시 넣지 않는다.
  • visible-lazy score: 이번 render에서 보인 stale Gaussian을 우선 갱신하고, 아직 최신 evidence로 확인하지 못한 row의 carve weight는 0으로 둔다.

초기 구현은 PGBA마다 모든 keyframe의 verification과 field insertion을 동기식으로 수행해 수 초씩 멈췄다. 305 PSNR 23.94 dB는 그 실패 구현의 결과다. lazy rebuild 뒤 PGBA field service 누적시간은 1253/305/1253_rot에서 각각 0.197/0.554/0.325 s로 제한됐다.
