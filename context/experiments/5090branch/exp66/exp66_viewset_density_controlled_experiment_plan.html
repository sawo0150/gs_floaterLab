재정의 이번에 검증할 관측사실

Primary scientific question

동일한 Phase-1 상태 z0=(Gaussian 파라미터, topology, Adam state), 동일한 RGB-only loss, 동일한 fixed-pose camera 생성법, 동일한 shuffle-without-replacement schedule, 동일한 GPU 시간 B에서, temporal하게 대표적인 view-set의 크기 K를 늘리면 held-out MSE 곡선이 어떻게 변하는가?

Eval(B; K,S,O,L,z0) = (1 / |V|) Σu∈V ℓRGB(u; θ(B))
K=set 크기 · S=set 구성법 · O=학습순서 · L=loss 종류 · B=실측 update GPU 시간

기존 결과는 여러 인자가 함께 바뀐 두 점을 비교했다. 후속 실험에서는 한 단계마다 위 함수의 인자를 정확히 하나만 바꾼다. 주 지표는 PSNR이 아니라 평균 MSE다. PSNR은 로그 변환이므로 그래프와 독자 친화적 보고에 함께 쓰되, curve fitting과 개선량 비교는 MSE에서 수행한다.

수학 모델 “필요 iteration”은 미리 정하는 상수가 아니다

고정된 view-set DK의 평균 학습 목적함수와 국소 곡률을 다음처럼 둔다. RGB-only로 고정하면 각 step에서 view를 균등 추출할 때 stochastic gradient는 이 set 평균 gradient의 unbiased estimator가 된다.

LDK(θ) = (1/K) Σv∈DK ℓv(θ),   gDK = (1/K) Σ gv,   HDK ≈ (1/K) Σ JvTWvJv

View가 너무 적을 때

K가 작으면 한 frame은 자주 반복되지만, set 평균 gradient가 전체 장면 목표에서 편향되고 약한 방향이 남을 수 있다. train loss는 빨리 내려가도 held-out ceiling이 낮을 수 있다.

View가 너무 많을 때

K가 크면 coverage와 conditioning은 좋아질 가능성이 있지만, 같은 budget에서 각 frame이 받는 반복 횟수와 epoch 수가 줄어 set이 충분히 성숙하지 못할 수 있다.

Cepoch(DK) = Σv∈DK cv,   Treq(K) ≈ Ereq(K) · Cepoch(DK)
E_req(K)는 필요한 epoch 수, c_v는 그 view의 실측 render+backward+Adam 시간

따라서 필요 iter = 고정 상수로 놓고 K ≈ budget / 필요 iter를 계산하면 순환논리가 된다. 필요한 epoch 수 자체가 K, set의 조건수, 초기 지도에 따라 달라진다. 먼저 K-sweep 수렴곡선에서 Ereq(K)를 실측하고, 그 뒤에야 budget에 맞는 최대 성숙 set 크기를 추정한다.

λmin과 gradient alignment의 위치

큰 λmin은 약한 parameter direction을 줄이는 set-level conditioning 설명이고, evaluation gradient와의 정렬은 한 update의 즉시 개선을 설명한다. 둘 다 유용하지만 이번 첫 sweep의 선택 rule로 사용하지 않는다. 먼저 결과를 만든 뒤 설명변수로 측정해야 Fisher-only 실패를 되풀이하지 않는다.

Candidate pool “30fps 전부”의 의미부터 고정한다

이번 density 실험에서는 keyframe/dense라는 기존 label을 버리고, fixed trajectory pose를 가진 RGB frame의 집합으로 통일한다. 그래야 K를 늘리는 행위가 “keyframe이 아닌 frame을 더 넣는 것”이 아니라 실제로 “서로 다른 RGB ray bundle을 더 넣는 것”이 된다.

Evaluation을 curve용과 lockbox로 나눈다

기존 idx%5==0 fixed_eval UID를 deterministic hash로 반씩 나눠 Vcurve와 Vlockbox를 만든다. 둘 다 training candidate에서는 제외한다. Stage A–C의 시간별 곡선, K 선택, Stage D reference gradient는 Vcurve만 사용한다. 진짜 30fps를 모두 학습할 때

같은 stream의 fixed_eval을 침범하면 안 된다. 별도의 평가 sequence 또는 별도의 카메라가 있을 때만 “30fps 전부 train” arm을 사용한다. 현재 aria1253 내부평가에서는 최대 admissible set까지만 쓴다.

Nested temporal set 생성

  1. 각 frame의 실제 timestamp로 1초 bin을 만든다. frame index/30 같은 가정은 사용하지 않는다.
  2. 각 bin의 admissible frame을 시간축 low-discrepancy 순서로 나열한다. 첫 점은 중앙, 다음은 가장 큰 시간 간격의 중앙을 재귀적으로 추가하고 동률은 작은 UID로 푼다.

  4. D_2 ⊂ D_4 ⊂ D_8 ...가 되도록 manifest generator가 subset 관계를 assert한다.
  5. 각 manifest에 target fps, effective fps, UID/timestamp, eval flag, pose-valid flag, parent manifest hash를 기록한다.

A2. K-sweep 본 실험

  • Arm: D02, D04, D08, D12, D16, Dmax.
  • 고정: exact Phase-1 snapshot, Adam reset mode, RGB-only, fixed trajectory pose, full Gaussian parameter scope, no pose/exposure optimization, no densify/prune, batch=1.
  • 순서: set마다 seeded shuffle without replacement. 한 epoch 안에서는 모든 frame이 정확히 한 번씩 등장한다.
  • 예산: 100초 update GPU time을 1차 공통 상한으로 사용하고 2/5/10/20/40/60/80/100초에 평가한다. 100초는 기존 dense 26k≈104초 관측에서 정한 사전값이며 결과를 보고 바꾸지 않는다.
  • 보조 x축: optimizer step, completed epoch, frame당 평균/최소 update 횟수를 함께 기록한다.
  • 반복: paired seed 0/1/2. 각 seed에서 만든 한 Phase-1 snapshot을 모든 K arm이 공유하고, 같은 번호를 Phase-2 sampler seed로 사용한다. 1차 매트릭스는 6×3=18 run이며 seed를 교차해 54 run으로 늘리지 않는다.
  • 안전: view 사전 forward audit에서 nonfinite/support failure를 검사한다. 본 실행은 fast loop를 사용하되 epoch 경계에서 numerical audit하고 실패 시 arm 전체를 무효 처리한다.
왜 같은 26,000 step만 보면 안 되나

D02와 Dmax는 한 epoch 길이가 크게 다르다. 같은 26k step은 D02에 훨씬 많은 반복 기회를 준다. 반대로 같은 epoch 수는 Dmax에 훨씬 큰 시간을 준다. 그래서 GPU time을 primary, step과 epoch를 보조 축으로 동시에 보고 “coverage 이득”과 “성숙 부족”을 구분한다.

분석 속도, ceiling, 성숙도를 따로 추정한다

Primary curve

EK(B) = E∞,K + AK exp[-(B/τK)βK]

이 식은 설명용 근사이며 결과를 강제로 맞추지 않는다. seed별 raw curve, monotone interpolation, AUC를 먼저 보고, fit residual이 작을 때만 τ와 E∞를 요약값으로 사용한다.

Budget에 맞는 set 크기

K*(B) = argminK∈𝒦 EK(B)    subject to    Ecompleted(K,B) ≥ Ereq(K)

여기서 Ereq(K)는 미리 지정하지 않고 Stage A 곡선에서 추정한다. 예를 들어 D16이 D12보다 ceiling은 낮은 MSE를 보이지만 30초 budget에서 아직 1 epoch도 못 돌아 뒤처진다면, “D16이 나쁜 set”이 아니라 “30초에는 성숙 불가능한 set”으로 해석한다. 최종 정책은 fps 하나가 아니라 K*(10s), K*(30s), K*(60s), K*(100s)의 Pareto envelope로 남긴다.

통계

  • MSE 차이는 seed 내 paired difference로 계산한다. 서로 다른 Phase-1 snapshot끼리 독립 비교하지 않는다.
  • 각 시간 milestone의 mean±std, paired bootstrap 95% interval, AUC의 paired interval을 보고한다.
  • 여러 K를 비교하므로 단일 final PSNR 최고값만 고르지 않는다. 전체 curve와 사전 지정 primary contrast(D02 vs D12, D12 vs Dmax)를 먼저 판정한다.
  • aria1253에서 찾은 K*는 진단 결과다. 정책 claim 전에는 다른 motion/scene에 threshold 재튜닝 없이 재현해야 한다.

Stage B 크기를 고정하고 view-set 구성법만 비교한다

Stage A에서 budget별로 성숙 가능한 중간 크기 Kmid 하나를 사전 규칙으로 고른다. 예: 60초에서 D12와 D16의 차이가 포화되기 시작하면 더 작은 D12를 사용한다. 이후 모든 selector가 정확히 같은 크기의 manifest를 만들고, 학습은 동일한 uniform epoch reshuffle만 사용한다.

“budget 안에서 최대한 novelty 있게 뽑는다”는 방향은 admission 문제를 scheduling과 분리한다는 점에서 맞다. 다만 순수 max-novelty는 overlap이 약한 극단 view, pose가 불안정한 view, 장면 분포를 대표하지 않는 view만 채울 수 있다. 따라서 이것을 정답으로 가정하지 않고 Fisher-only arm으로 그대로 시험하며, representative coverage arm을 별도로 둔다.

모든 selector는 최종 held-out image나 validation gradient를 보지 않는다. pose validity와 최소 raster support는 정보 선택 이전의 안전 gate로만 사용한다. selector 계산 시간은 selection_seconds로 따로 측정하고, 품질이 같을 때 더 싼 selector를 우선한다.

각 epoch가 끝나면 모든 arm이 set의 각 frame을 똑같이 한 번씩 사용한다. 차이는 한 epoch 내부 순서뿐이다. 따라서 novelty-first가 초반엔 느리고 epoch 경계에서는 같아진다면 “정보가 나쁜 것”이 아니라 연속된 gradient 방향 변화가 optimizer에 불리한 순서 효과라고 해석할 수 있다.

Stage D Fisher·λmin·gradient alignment는 사후 진단으로 연결한다

Stage A–C의 실제 곡선이 확보된 뒤에만 proxy가 무엇을 설명하는지 본다. 여기서 reference gradient는 training에 쓰지 않는 작은 audit set R의 평균 gradient다.

gR = (1/|R|) Σr∈R ∇θℓr(θ),   align(v) = gRTgv / (||gR||·||gv||+ε)
ΔEactual(v) = ER(θ) − ER(AdamStep(θ,gv))
snapshot → candidate 1-step → audit forward → rollback; 진단 전용이며 online scheduler 비용에는 포함하지 않음
  1. 초기, 중기, 후기 checkpoint에서 candidate 50~100개를 고정 추출한다.
  2. 각 candidate의 coverage/Fisher score, residual, gradient alignment, pose confidence, 실제 one-step Δaudit-MSE, update ms를 기록한다.
  3. Spearman 상관과 top-decile precision을 시점별로 계산한다. 전체 시점을 섞어 한 상관계수로 만들지 않는다.
  4. set-level에서는 randomized Lanczos/JVP 또는 저차원 block Gauss–Newton proxy로 λmin, condition proxy를 측정한다. full 3DGS Fisher determinant를 직접 만들지 않는다.
  5. λmin이 높은 set이 ceiling만 높이는지, τ도 낮추는지 Stage A/B curve와 연결한다.
금지

이 diagnostic audit set을 이용해 Stage A의 K나 Stage B selector hyperparameter를 반복 조정하지 않는다. 그러면 “왜 빨랐나”를 설명하는 측정이 다시 selection feedback이 되어 final-eval 과적합이 생긴다.

Go 조건

  • RGB-only에서도 K 증가에 따라 AUC 또는 time-to-X가 paired seed에서 개선된다.
  • 중간 K 이후 포화 또는 budget별 교차가 보여 K(B)를 추정할 근거가 생긴다.
  • 개선이 iteration뿐 아니라 GPU time에서도 유지된다.

Stop / 재해석 조건

  • K 효과가 RGBDN 제거 후 사라지면 기존 결과는 주로 loss regularization 차이였다.
  • E∞만 좋아지고 τ/AUC 초반이 나빠지면 dense는 ceiling 개선이지 속도 개선이 아니다.
  • shuffle-epoch에서 기존 우위가 사라지면 pool보다 복원추출 sampler의 우연이 컸다.

과적합 방지 fps를 scene-specific 숫자로 굳히지 않는다

  1. 결과를 보기 전에 K grid, 100초 budget, milestone, primary contrasts, seed를 manifest와 config에 고정한다.
  2. aria1253은 mechanism-identification scene으로만 사용한다. 여기서 고른 rule은 aria305/rot/다른 motion regime에 숫자 재조정 없이 적용한다.
  3. online scheduler는 fixed_eval/validation MSE를 매 step 읽지 않는다. validation은 offline 분석과 진단에만 쓴다.
  4. 최종 rule은 “12fps”가 아니라 budget에서 최소 성숙 epoch를 만족하는 가장 큰 대표 set처럼 scale-free하게 쓴다.
  5. view rate는 timestamp 기반 effective fps, 비용은 update GPU ms, 성숙도는 completed epoch로 보고해 GPU/해상도가 바뀌어도 해석 가능하게 한다.
  6. geometry metric을 별도로 보고 PSNR 향상이 puffy/floater geometry 악화와 교환된 것은 아닌지 확인한다.

권장 순서

먼저 Stage A의 18개 RGB-only paired run으로 E(B;K)를 얻는다. 이것이 “dense할수록 빠르다”를 순수한 view-set 크기 효과로 바꾸는 최소 증거다. 그다음에만 같은 K에서 novelty/Fisher admission을 시험하고, 마지막에 same-set 순서를 시험한다.

Water-filling이나 frame별 utility는 장기적인 최종 형태일 수 있지만, 현재 단계에서 넣으면 admission과 replay가 다시 한 식 안에서 섞인다. v1의 이상적인 학습법은 더 단순하다: budget으로 감당 가능한 크기의 대표적인 fixed set을 만들고, 모든 frame이 동등하게 성숙하도록 epoch reshuffle한다. 그 baseline을 이기는 proxy만 다음 scheduler 구성요소로 승격시킨다.
