map()-only causal replay 구현 및 엄격 streaming 검증

Stage B–F에서 얻은 “B1 + shuffle-without-replacement” 결론을 실제 VIGS incremental 경로에 옮겼다. background_polish_step()은 실행하지 않는다.

결론: 기제 구현은 성공했다. 고정 경계 reference에서 3/3 반복이 27.19–27.20 dB, 97.32–97.39초, background step 0, tail update 0을 만족했다. 그러나 이 결과는 아직 start/freeze와 12 fps admission이 aria1253에 고정돼 있다. 따라서 바로 production 최종안으로 merge할 단계는 아니며, 구현 가능한 mechanism reference 단계다.

  • 정규 keyframe은 기존 frontier map()이 담당하고, idle replay는 dense RGB만 담당한다. 이는 source를 임의로 편향한 것이 아니라 이미 서비스된 keyframe을 중복 배정하지 않는 역할 분리다.
  • 새 dense frame은 미완료 epoch의 무작위 위치에 삽입한다. 항상 맨 앞에 두지 않아 novelty-first 실패를 반복하지 않는다.
  • replay는 densify/prune, opacity reset, topology scale clamp를 건드리지 않는다. 다만 동일 Gaussian Adam과 RGB loss를 사용한다.
  • replay 전용 step으로 xyz learning-rate schedule을 진행한 뒤 frontier learning rate를 복원한다.
  • idle_map_rr가 켜지면 config에 background polish가 켜져 있어도 강제로 끈다.

5. 현재 merge 판단

  • merge 가능한 부분: CUDA-free causal shuffle queue, map(replay_only) 경로, B1 semantics, source 역할 분리, replay LR 복원, background 강제 차단, 로그/재현 스크립트.
  • reference로만 유지할 부분: start 700, late 650, freeze 800, stride 5 offsets 1/4. 이 값들은 mechanism regression용이지 일반 scheduler model이 아니다.
  • 채택 금지: sequential burst 2, 항상-on stationary mapping, Gaussian-count 2배 auto-freeze v1.

다음 연구 단위는 frame 번호 sweep가 아니라, topology update의 실제 held-in causal progress/ms와 replay progress/ms를 동일 단위로 기록하는 것이다. 그 신호가 여러 장면에서 phase 전환과 상관된 뒤에만 horizon-free controller를 채택한다.
