# 3.3 Entropy-Regularized Count-Balanced Block Reshuffling (★C2) — 무엇을 쓸 것인가 (v01, 2026-09-05)

> 한 줄 claim: **count imbalance 감소와 random shuffle 근접을 하나의 entropy-regularized 문제로 묶으면 해가 `p(i) ∝ exp(−βn_i)` 다**
> ⚠ claim boundary: exp72에서 lifetime 균등화는 **실패**. P03 재검증 전 "균등화한다"고 쓰지 말 것.

## 이 절의 역할

§3.1이 pool 크기를, §3.2가 pool 구성원을 정했다. 남은 결정은 **순서**다.
핵심 논지는 "informative한 view를 먼저 학습하자"가 아니라, **priority score로 정렬하면
실제 update 분포가 `Σ_v p_v L_rgb(v)` 로 바뀌어 §3.2가 만든 trajectory 비중을 optimizer가
다시 왜곡한다**는 것이다. 그래서 순서 정책은 별도 utility 가정 없이
"count 불균형을 줄이되 random shuffle에서 멀어지지 않는" 문제로 세운다.

## 반드시 넣을 내용

- [ ] **왜 priority ordering이 아닌가** (2문장 + 근거)
  - membership이 만든 분포를 optimizer가 재왜곡한다
  - 실측: novelty-first / residual-first가 shuffle보다 AUC MSE **10–11% 나쁨**,
    with-replacement가 **1.7% 나쁨** (exp66 Stage C)
- [ ] **Count imbalance potential에서 분포 유도** (본문에는 결과만, 전문은 Supplementary)
  - `Φ(n) = ½ Σ_i (n_i − n̄)²`
  - `Δ_i Φ = n_i − n̄ + ½(1 − 1/N)` — 마지막 항은 모든 i에 공통 (**이게 핵심**)
  - `p_t = argmin_{p∈Δ_N} [ Σ_i p_i(n_i − n̄) − τH(p) ]`
  - Lagrangian → `p_t(i) = exp(−βn_i) / Σ_j exp(−βn_j)`, `β = 1/τ`
  - τ>0 이면 entropy가 strictly convex → simplex 내부 **유일** 최소해
  - `n̄` 은 공통항이라 구현식에서 소거됨을 명시 (수치 안정성 이점)
- [ ] **K-view statistical block** (여기가 실제로 품질을 만든 부분)
  - one-step categorical sampling은 같은 view를 연속 선택해 coverage가 깨진다
  - block 시작 시 count를 `n_i^(b)` 로 **고정(snapshot)** 하고,
    remaining set에서 sequential weighted sampling **without replacement**
  - `W_b^(0) = A_{t_b}`, `p_{b,k}(i) ∝ exp(−βn_i^(b))` for `i ∈ W_b^(k)`,
    `W_b^(k+1) = W_b^(k) \ {I_{b,k}}`
  - K개를 뽑거나 remaining이 비면 block을 닫고, 다음 block은 그 시점의 pool로 재생성
  - block 중간에 도착한 view는 **다음 block부터** 참여
- [ ] **두 극단과 정확한 random-shuffle 문장**
  - `β=0`: 현재 block의 모든 ordered K-subset에 균등.
    **`K ≥ N_t` 일 때에만** 전체 pool의 `N_t!` permutation에 정확히 균등 ← 이 조건 필수
  - `β→∞`: randomized least-count에 접근
  - 유한 β: 덜 학습된 view에 soft preference, 모든 remaining view에 non-zero support
  - count가 비슷해지면 weight가 같아져 uniform without-replacement로 자동 복귀
- [ ] **Entropy 측정 정의**
  - `ρ_H = Σ_{b,k} H(p_{b,k}) / Σ_{b,k} log|W_b^(k)|`
  - "같은 remaining support 대비" 정규화값임을 반드시 함께 쓴다
- [ ] **§3.1과의 관계 한 문단** — token admission이 있어야 `n_i` 가 ordering에만 쓰이고,
  admission 시점과 cardinality에 영향을 주지 않는다. exp72의 실패가 바로 이 지점이었다.
