# 3.2 Entropy-Regularized Count Balancing (ERCB) — 무엇을 쓸 것인가 (v02, 2026-09-06)

> 한 줄 claim: **선택 횟수 불균형을 entropy 정규화 문제로 두면 해가 유일하게 정해진다.**
> 5문단, 수식 3개, 93줄 = 0.85 p.
>
> ★ P1 은 **"정확한 대상"이 아니라 "이상적 스케줄이 원하는 두 가지"**로 연다.
> 그래야 목적함수의 **두 항이 각각 (a)(b) 에 대응**하는 것이 보인다 —
> entropy 가 수학적 편의가 아니라 **요구사항 하나**임이 드러난다.

## 유도의 뼈대 — 이상적 요구에서 세 번 완화한다

chen2026cover §4 의 "정확 → 완화 → 실용"을 한 소절로 압축한 형태.

```
정확     전체 run 의 최종 count 분산을 최소화하는 선택 시퀀스
         ← 도착 과정이 아직 안 알려진 조합 최적화. 온라인에서 못 푼다
  ↓ 완화 1 (P2)
         한 step greedy: potential Φ 의 즉각 증가량만 최소화
         → 결정론적 "가장 적게 뽑힌 것" 규칙. 무작위성이 사라진다
  ↓ 완화 2 (P3)
         결정론적 argmin 대신 entropy 정규화된 기댓값 최소화
         → Gibbs 해. 유일하다
  ↓ 완화 3 (P4)
         매 선택마다 p 를 다시 계산하지 않고 block 시작 시점 count 를 고정
         → Plackett–Luce 비복원 추출
```

★ 완화 단계를 명시하면 **P4 의 "1차 근사"가 비로소 말이 된다.** v01 은 근사라고만 하고
*무엇의* 근사인지가 없었다.

## 문단 계약

| # | 하는 이야기 | 줄 | 수식 |
|---|---|---:|---|
| **P1** | **이상적인 스케줄이란 무엇인가.** 집합은 무한정 자라는데(§3.1) 단위시간당 update 는 늘지 않으므로 **view 당 노출이 줄고 순서의 중요성이 커진다.** 이상적 스케줄이 원하는 것 둘:<br>**(a) 섞임** — 연속한 update 가 상관 없는 gradient 를 봐야 한다. 궤적 순서대로 넣으면 연속 step 이 거의 같은 장면을 보아 국소만 쫓고 전역 진행이 정체된다. **셔플링이 존재하는 이유**<br>**(b) 전후반 편차 제한** — 자라는 집합에서 균등 추출하면 초반 view 가 훨씬 많이 노출되어 **시작은 선명하고 끝은 흐린 지도**가 된다. 완전 균등까지는 아니고 편차를 눌러야 한다<br>**이 둘은 서로 당긴다** — 최대 섞임 = 균등 = 최대 편차 / 완전 균등화 = 결정론 = 섞임 0. 그래서 **두 휴리스틱의 배합이 아니라 원리적 손잡이**가 필요하다 | 16 | |
| **P2** | **(b) 를 potential 로 형식화.** `Φ` 정의 (4). `Δ_iΦ = n_i − n̄ + ½(1−1/N)` — **inline.** 마지막 항이 `i` 에 무관 → greedy 는 **가장 적게 뽑힌 것 고르기**로 환원. **결정론적이므로 P1 이 경고한 (a) 를 그대로 잃는다** | 10 | (4) |
| **P3** | **DERIVING (완화 2) + 등식 감사.** ★ **(a) 를 패치가 아니라 항으로 되살린다** — 최적화 문제를 **display (5)** 로 올린다. 첫 항이 (b), 둘째 항이 (a), `τ` 가 P1 이 요구한 손잡이. `τ→0` 결정론, `τ→∞` 균등. **"한 step 에서 count 는 고정"**이라 목적이 `p` 에 대해 선형 + τ×음엔트로피 = 강볼록 → **유일한 Gibbs 해**(표준, 인용). ★ **우리 것인 단계는 소거**: `Δ_iΦ` 가 `n_i` 와 공통항만큼만 다르고 그게 정규화에서 사라져 (6) 이 된다. **Lagrangian 대수는 supplement** — 반 구절로 밝힌다. 이어서 **등식 감사**: `β=0` 은 `K ≥ N_t` 일 때만 random reshuffling 과 일치, `K<N_t` 면 block 은 순열이 아니라 부분집합. 그때도 **수렴 보장은 안 가져온다** | 20 | **(5)(6)** |
| **P4** | **EXTENSION (완화 3) + 언제 정확한가.** **첫 문장에서 이름을 밝힌다** — 가중치 `exp(−βn_i)` 로 K개를 순차 비복원 추출하는 것은 **Plackett–Luce** 추출(= Gumbel-Top-k). (5)를 정확히 적용하려면 매 선택마다 `p` 재계산이 필요하나, block 시작 count `n_i^(b)` 를 고정해 K개를 뽑는다. ⚠ **"1차 근사"라고 쓰지 말 것 — 확인 전까지.** 뽑힌 view 는 후보에서 빠지므로 그 count 갱신이 **남은 후보의 상대 가중치를 못 바꾸고**, 공통항은 어차피 소거된다. 모델대로면 고정 추출이 **정확**하며 이는 우리가 하던 말보다 강한 진술이다. 깨질 수 있는 경우: `K` 가 후보 수를 넘어 wrap 하거나, `n_i` 가 **선택 시점이 아니라 사용 시점**에 증가할 때. **exp72 코드 확인 후 조건을 쓴다.** 남은 무작위성은 `ρ_H` 로 계측(정의는 §4) | 22 | |
| **P5** | **대리와 목표가 갈라지는 지점.** ① 숫자 — middle/first 0.758 → **0.520** 인데 held-out PSNR 은 **+0.362 dB**, 다른 궤적은 0.971, 더 큰 `β` 는 0.605 까지만 회복하며 entropy 하락. **일반적 개선 주장 안 함.** ② **가설을 대되 가설이라고 표시** — raw count 를 맞추면 늦게 들어온 view 를 끌어올리는데, 아주 늦게 들어온 view 는 남은 update 자체가 적어 못 따라잡는다. 후반 내용이 많은 궤적에서 그 부족분이 지배적일 수 있다. **테스트하지 않았다**고 쓴다. ③ **독자에게 뭘 뜻하는지** — lifetime equality 자체가 목적이라면 이 방법은 그 도구가 아니다 | 16 | |

### 유도를 어디까지 보이나 — chen2026cover 의 기준

chen 은 수식을 19개 쓰면서도 **표준 결과는 이름만 댄다**:
*"The proof of Eq. (7) is **automatic by Rayleigh quotients**."* /
*"by the **matrix determinant lemma**."* 대수는 **자기 고유의 사슬**에만 쓴다.

우리 Lagrangian 전개(∂L/∂p_i = 0 → `p_i ∝ exp(−Δ_i/τ)`)는 **교과서**다 —
simplex 위 선형 + entropy 정규화의 해가 Gibbs 형태라는 것은 통계물리·OT·maxent RL 에서
전부 인용하고 넘어간다. 유도해 보이면 오히려 *"이게 새롭다고 생각하나"* 로 읽힌다.

**정작 우리 것은 대수가 아니라 소거 한 줄이다:**
`Δ_iΦ = n_i − n̄ + ½(1−1/N)` 에서 뒤 두 항이 `i` 에 공통이라 정규화에서 사라져
`exp(−Δ_iΦ/τ) → exp(−βn_i)` 가 된다. **일반적 결과가 우리 규칙이 되는 지점**이므로 본문에 둔다.

⚠ *"strictly convex"* 가 성립하려면 `Δ_iΦ` 가 `p` 에 안 딸려야 한다.
`n` 은 과거 선택의 결과라 **한 step 안에서는 상수**가 맞지만, 그 사실을 **명시**해야 한다.
안 쓰면 *"n 이 p 에 의존하는데?"* 를 맞는다.

## 등식 감사를 P3 에 두는 이유

chen2026cover §4.1 은 등식이 깨지는 **바로 그 지점**에서 감사한다:

> *"However, note that with additional constraints, Eq. (7) is **no longer equality**.
> Rather, we have the tight bound by Cauchy--Schwarz ... **Regardless**, minimizing Eq. (8)
> subject to additional constraints still applies upward pressure to the FIG."*

별도 문단으로 빼지 않는다. 뒤로 미루면 **사과처럼** 읽히고, 제자리에 있으면 **유도의 일부**로 읽힌다.
