작성일: 2026-09-19. 사용자 결정: **기하 방법은 Carve로 서술한다.**

이번 수정 방향: **DROID-SLAM 기반 frontend**, **실시간 온라인 매핑의 실용성**, **문단 3 안의 수식과 설명**, **현재 논문 TeX 표에 근거한 결과 문장**. 본문은 동료 연구자와 일반 공학 독자가 읽을 수 있도록 쓰고, 문제 제기와 차분한 사실 설명의 강약을 조절한다.

이 문서는 Extended Abstract의 2절을 작성하기 위한 한국어 구상과 문단 초안이다. 사용자 지정에 따라 문구 계획은 `02_method/writingplan/`에서 관리하고 업데이트한다. 그림 관련 계획은 기존 `02_method/plan/`에 둔다. 학술논문 원본은 `paper/latex/`이며, 이 문서에서는 휴먼테크 분량에 맞게 압축한다.

Carve를 쓰기로 한 서술 방향과 Carve의 성능 검증 완료 여부는 구분한다. Hit·Carve+Hit 후보를 초고의 방법 설명에 나열하지 않는다. Carve의 ENLL/MARG 세부 선택, 가중치, 비교 모델 및 성능 수치는 구현·실험 자료 확인 후 채운다.

## 1. 먼저 정할 이야기와 2절 제목

**전달할 이야기:** 로봇과 웨어러블 기기가 관측 중에 주변의 3D 지도를 계속 갱신할 수 있도록, 실시간 온라인 매핑에서 주어지는 제한된 학습 기회를 효율적으로 활용한다. 도착한 영상의 편입과 재학습을 조절하고, 깊이 관측을 이용해 빈 공간의 불필요한 Gaussian opacity를 억제한다.

추천 제목:

> **2. Efficient Real-Time Online Gaussian Mapping**
>
> 한국어 작업 제목: 효율적인 실시간 온라인 Gaussian 매핑

실용성은 “사용 중에 들어오는 관측으로 지도를 계속 갱신한다”는 사용 맥락에서 설명한다. 구체적인 방법은 제한된 학습 기회의 활용으로, 그 효과는 Fig. 2의 영상 품질과 Fig. 3의 기하 비교로 연결한다. Frontend는 **DROID-SLAM 기반 frontend**로 소개하고, 새 기여는 관측 편입·학습 배분·Carve에 둔다. Frontend 자체를 새로 제안했다고 쓰지 않으며, 기반 기술 인용과 비교 방법의 출처는 참고문헌·표·캡션에서 식별할 수 있게 유지한다.

**Introduction과의 연결:** 현재 휴먼테크 메인 원고는 [paper.tex](../../../HumanTeck_Song_s_intern/paper.tex)다. 동료가 작성한 Introduction에서 로봇·웨어러블의 온라인 매핑 필요성, 제한된 예산에서의 영상·기하 품질, Growth·ERCB·Carve의 기여를 이미 소개한다. 2절 개요에서는 필요성과 기여를 다시 주장하지 않고 입력·추정값·지도 갱신의 실제 흐름으로 바로 들어간다. 실용성은 관측이 들어오는 동안 지도를 갱신하는 동작으로 이어받는다. Introduction의 ERCB와 문단 3의 Entropy-Regularized View Sampling은 같은 방법을 가리키므로 영문 통합 시 명칭을 맞춘다.

작성자 메모: 실시간 온라인 매핑을 연구 목적과 운용 조건으로 앞세우되, 현재 품질 표만으로 특정 FPS, 입력 속도 준수, 온디바이스 실행, 실측 지연시간을 달성했다고 쓰지 않는다. 시간 측정이 없는 결과에는 “실시간 조건을 위한 제한 예산에서의 품질 개선”이라는 범위를 유지한다.

### 추가 피드백 — 문제 제기와 사실 설명의 강약

사용자가 전달한 송채현 선배님의 피드백을 반영한다. 핵심은 강한 주장이나 반전 표현을 반복하기보다 독자가 문제를 이해하고 동작을 따라갈 시간을 주는 것이다. `must`, `need`, `require`의 강도는 문맥에 따라 달라지므로 기계적인 치환 규칙으로 쓰지 않는다.

- **개요:** Introduction의 사용 상황·문제 제기를 반복하지 않고, 입력과 지도 갱신 방식을 차분하게 설명한다.
- **Growth:** 추가 영상의 이점부터 설명한다. 제한된 update가 분산된다는 문제는 한 번 제시하고, 이후에는 규칙을 설명한다.
- **Sampling:** 편입 시점이 다르면 선택 횟수가 달라질 수 있다는 사실에서 시작한다. 수식 앞에는 목적을, 뒤에는 각 항의 뜻을 둔다.
- **Carve:** 빈 공간의 floater를 한 문장으로 설명한 뒤 깊이와 opacity의 역할을 풀어 쓴다. “근본적 결함”, “반드시 해결”, “완전히 제거” 같은 표현은 쓰지 않는다.
- **결과:** 비교 조건과 수치를 전달한다. 효과를 매 문장마다 “입증했다”, “획기적으로 개선했다”로 강조하지 않는다.

영문에서는 `however`를 문단마다 반복하지 않고 실제 대조가 필요한 위치에만 사용한다. 일반적인 시스템 동작은 `uses`, `estimates`, `selects`, `updates`처럼 구체적인 동사로 설명한다. 한국어에서도 모든 문단을 “하지만/그러나”로 시작하지 않는다. 최종 단어 선택보다 내용의 연결과 이해 가능성을 먼저 맞춘다.

## 4. 바로 다듬어 쓸 한국어 문단 초안

아래는 방법 네 문단과 결과 한 문단의 한국어 초안이다. 전문 용어는 처음 나올 때 의미를 덧붙인다. 결과 문장은 현재 `paper/latex/sec/5_results.tex`에 실린 표를 기준으로 작성하며, 아직 없는 Carve 수치만 별도 보류한다.

### 문단 1 — 시스템 개요

제안 프레임워크는 순차적으로 들어오는 RGB 영상과 IMU 관측으로 Gaussian 지도를 점진적으로 구축한다. DROID-SLAM 기반 frontend에서 얻은 카메라 자세와 깊이로 지도를 초기화하고, 새로 관측한 영역으로 확장한다. 지도 학습에서는 View Growth가 사용할 영상을 편입하고 View Sampling이 업데이트에 사용할 영상을 선택하며, Carve loss는 깊이 관측을 이용한 기하 제약으로 함께 적용된다.

도입 방식: 수상자의 Method처럼 프레임워크의 동작과 구성부터 설명한다. 개요 문단에서는 그림을 언급하지 않고, 이후 각 방법의 구체 설명에서 해당 패널을 참조한다.

### 문단 2 — Optimization-Guided View Growth

위치 추정을 위해 선택한 대표 영상인 키프레임 사이에도 지도 학습에 활용할 시점과 색상 정보가 있다. 학습 영상을 늘리면 이 정보를 활용할 수 있지만, 같은 수의 업데이트를 더 많은 영상에 나누어야 한다. 우리는 완료된 지도 학습 업데이트(mapping update) 수에 맞춰 영상 집합을 확대한다(Fig. 1(a)). 업데이트가 κ회 완료될 때마다 이미 도착한 후보 영상 한 장을 추가로 편입할 수 있고, 기존 영상은 재학습을 위해 유지한다. 따라서 촬영이 얼마나 이어질지 미리 알지 못해도 실제 학습 진행에 맞춰 새 관측을 포함할 수 있다.

### 문단 3 — Entropy-Regularized View Sampling

일찍 편입된 영상은 늦게 편입된 영상보다 학습에 선택될 기회가 많다. 우리는 지금까지 적게 선택된 영상에 학습 기회를 보완하면서, 여러 영상이 확률적으로 선택될 수 있도록 다음 목적함수로 선택 확률을 정한다(Fig. 1(b)).

$$
\min_{\mathbf p\in\Delta}\;\sum_i p_i\Delta_i\Phi-\tau H(\mathbf p).
$$

여기서 p_i는 영상 i의 선택 확률이고, Δ는 확률이 음수가 아니며 합이 1인 분포들의 집합이다. Φ는 평균 선택 횟수로 정규화한 누적 선택 횟수의 분산이며, Δ_iΦ는 영상 i를 한 번 더 선택했을 때의 분산의 변화량이다. 첫째 항은 적게 선택된 영상을 우대하고, 엔트로피 H를 사용하는 둘째 항은 선택이 소수 영상에 지나치게 집중되는 것을 완화한다. τ>0는 두 항의 비중을 조절한다. 이 확률에 따라 서로 다른 K개 영상을 중복 없이 뽑아 다음 K회의 업데이트에 한 장씩 사용한다.

### 문단 4 — Causal Free-Space Carve Loss

색이 잘 맞는 지도에도 실제 표면 앞의 빈 공간에 떠 있는 Gaussian, 즉 floater가 남을 수 있다. 카메라에서 관측 표면까지의 깊이는 그 앞의 빈 공간을 판단하는 근거가 된다. Carve loss는 현재까지 확보한 깊이와 그 불확실성, 표면 주변의 여유 구간을 고려하여 빈 공간에 놓인 Gaussian의 불투명도(opacity)를 낮춘다(Fig. 1(c)). 이 항은 opacity에 대한 학습 신호를 기존 지도 학습에 더하며, Carve 자체가 Gaussian의 위치나 형상을 직접 갱신하지는 않는다.

편집 메모: 위 opacity-only 설명은 현재 `4_method.tex`의 Carve gradient 경로에 따른다. 전체 학습에서 위치·형상이 고정된다는 뜻이 아니다. 기존 mapping loss는 해당 변수들을 계속 갱신할 수 있다. Carve가 새 표면을 만들거나 floater를 표면으로 이동시킨다고 쓰지 않는다.

### 문단 5 — 현재 TeX 표에 근거한 결과 초안

공개 RGB+IMU 벤치마크인 RPNG·UTMM과 Meta가 개발한 Aria 안경으로 직접 수집한 데이터에서 평가했다. 학습에 사용하지 않은 영상의 평균 PSNR은 비교 기준 방법보다 각각 1.60·0.52·2.45 dB 높았다. Fig. 2와 Fig. 3에서는 각각 영상 재현 품질과 Carve 적용 유무에 따른 지도 기하를 비교한다.

편집 메모: 둘째 문장은 `tab:rendering_comparison`의 데이터셋별 차이이며 RPNG·UTMM·자체 Aria 순서다. 절대 PSNR과 개선치를 모두 나열하지 않고 개선치만 남겨 데이터셋 설명의 공간을 확보했다. 비교 기준 방법의 정식 명칭과 인용, 예산 조건은 최종 표 또는 Fig. 2 캡션에서 식별되도록 한다. 이 문장은 품질 결과이며 실시간 처리 속도의 실측 결과가 아니다. 해당 Ours 행에 Carve까지 포함됐는지는 run 구성을 확인한 뒤 기술하고, 지금 수치를 Carve의 효과로 귀속하지 않는다. 셋째 문장은 계획한 그림의 역할을 설명하며, 실제 Fig. 2–3을 완성한 뒤 제출본에 반영한다.

**데이터셋 표현:** RPNG·UTMM이 RGB와 IMU를 제공하는 공개 평가 데이터라는 점을 짧게 전달한다. “인기 있는” 또는 “널리 쓰이는”이라는 사용 빈도 주장은 별도로 입증하지 않았으므로, 본문은 “공개 RGB+IMU 벤치마크”로 쓴다. 데이터셋에 다른 센서 자료가 함께 들어 있어도 여기서는 사용하는 입력을 설명한다. 자체 Aria는 Meta가 배포한 공개 데이터셋이 아니라 **Meta의 기기로 우리가 직접 수집한 데이터**라는 구분을 유지한다.

데이터셋·기기 설명의 확인 출처: [RPNG 공식 데이터셋](https://github.com/rpng/ar_table_dataset), [UT-MM 공식 프로젝트](https://vita-group.github.io/MM3DGS-SLAM/), [Meta의 Project Aria 소개](https://about.fb.com/news/2020/09/announcing-project-aria-a-research-project-on-the-future-of-wearable-ar/). 직접 수집했다는 내용은 사용자 설명과 프로젝트 기록에 따른다. 이 링크들은 작성 근거이며 제출본에서는 필요한 참고문헌 인용으로 정리한다.

**전체 결과 뒤에 ERVS만 설명하던 구성을 바꾼 이유:** 전체 비교와 Sampling만의 ablation을 한 문단에 두면 Growth와 Carve의 역할이 빠진 것처럼 읽힌다. 균형을 맞추려고 세 방법의 수치를 모두 늘어놓으면 2쪽 초록의 결과 문단이 길어진다. 따라서 문단 5는 전체 성과와 그림의 역할에 집중한다. Growth·ERVS의 정량 ablation은 본논문 표에 두고, 초록에 남길 Carve ablation은 Fig. 3의 타원체와 캡션으로 설명한다. SSIM·LPIPS는 이 문단에서 생략한다.

그림 완성 후에는 셋째 문장을 실제 관찰된 RGB·기하 효과를 함께 설명하는 문장으로 교체할 수 있다. Carve의 region GT 지표와 held-out PSNR은 Fig. 3 캡션에 기록하고, 아직 확보하지 않은 감소율이나 표면 보존을 본문에 먼저 단정하지 않는다.

## 5. 문단 3의 수식과 가독성

수식은 문단 3에 실제로 배치했다. **선택 기회 차이라는 관찰 → 확률을 정하는 목적 → 목적함수 → 기호와 두 항의 뜻 → 중복 없는 K회 선택** 순서로 읽힌다.

- 엔트로피를 아는 독자만 이해할 수 있게 두지 않고, “선택이 소수 영상에 집중되는 것을 완화한다”는 동작을 바로 설명한다.
- 확률 simplex는 한국어 본문에서 “음수가 아니고 합이 1인 확률 분포들의 집합”으로 푼다.
- Φ의 정규화 방식은 현재 Method의 선택 횟수 분산 정의를 따른다. 분산 전개, 변화량 유도, softmax 해를 각각 별도 수식으로 늘리지 않는다.
- Growth는 “κ회 완료된 update마다 한 장 편입 가능”이라는 문장으로, Carve는 깊이와 opacity의 관계 및 Fig. 1(c)로 설명한다.
- 영문으로 줄일 때도 수식을 고립시키지 않는다. 기호 정의와 첫째·둘째 항의 역할을 우선 보존한다.

Dense supervision의 pose/init은 사전 실행의 고정 replay이므로 end-to-end strict online 증거로 쓰지 않는다. 주 비교의 대응 실험인 exp94도 mapping-only fixed-work 비교다. 동일 physical render 조건을 동일 Adam update 수나 동일 wall-clock 시간으로 바꾸어 설명하지 않는다. 실용성은 **실시간 운용을 위한 관측 활용과 제한 예산에서의 품질**로 설명하고, 실제 입력 속도를 따라가는 성능은 별도 시간 측정으로 제시한다.

세 표는 장면 구성과 계약이 다르므로 “주 비교도 19장면, 15 updates”인 것처럼 합치지 않는다. `tab:abl`과 `tab:order`의 SSIM/LPIPS는 비어 있으므로, 이 두 ablation에서 세 지표가 모두 개선됐다고 쓰지 않는다. 본문에 반영한 수치와 아직 없는 Carve 결과를 분리한다.
