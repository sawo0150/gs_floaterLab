# HumanTeck Fig. 3 — 전체 방법의 품질 도달 효율

상태: 설계 제안. 신규 학습/평가, 곡선 수치 생성, TeX 수정은 하지 않았다.
참고 스케치: [사용자 스케치](../references/KakaoTalk_20260921_102823689.jpg).

최신 결정: 사용자 요청으로 x축은 **Mapping iterations (×10³)**를 사용한다.
아래 render 축 제안은 최초 설계 기록이며, [iteration 시안과 프롬프트](../mockup/prompt_v02.md)가 우선한다.

## 그림의 질문

동일한 causal 입력 스트림에서 Ours가 VIGS-SLAM baseline과 같은 held-out
재구성 품질에 도달하는 데 더 적은 mapping work가 필요한가?

Fig. 2는 같은 최종 예산의 렌더링 차이를 보여준다. Fig. 3는 중간 checkpoint를
포함해 그 품질에 도달하는 과정을 보여준다. 여기서는 전체 방법 두 곡선에 집중하고,
KF-only/dense 및 Random/ERCB 구성요소 ablation은 별도 그림으로 둔다.

## 권장 도판

- 한 단 폭 약 86 mm, 높이 약 70–80 mm. 최종 조판에서 글씨 7–8 pt 이상 확인.
- 위 약 2/3: 장면 하나의 PSNR–work 곡선. Baseline은 주황 점선,
  Ours는 청록 실선. 실제 checkpoint는 작은 marker로 표시한다.
- x축: `Training view renders (×10³)`. 학습 forward/backward에 사용한 개별 view
  render의 누적 수이며 evaluation render는 제외한다.
- y축: `Held-out PSNR (dB) ↑`. 전체 trajectory에 걸친 고정 held-out 집합의
  per-image PSNR 산술평균. 각 checkpoint마다 같은 UID, pose, mask, 해상도를 사용한다.
- 목표 품질 q에 옅은 수평 점선, 양쪽 도달 위치에 세로 보조선,
  두 위치 사이 수평 화살표로 `x% fewer training renders`를 표시한다.
  숫자는 실제 양쪽 도달 비용이 확보되고 차이가 있을 때만 넣는다.
- 아래 약 1/3: 동일 중간 work W*에서 Baseline / Ours / GT의 같은 held-out
  시점 ROI를 3열로 배치한다. 두 render는 위 곡선의 동일 x 위치와 연결한다.
  설명에 그래프는 전체 held-out 평균, 이미지는 그중 한 view라는 점을 밝힌다.
- 스케치의 하강 모양은 강제하지 않는다. PSNR은 상승 곡선이며 비단조 변화도 보존한다.
  하강 지표가 꼭 필요하면 held-out LPIPS를 별도로 고려할 수 있지만,
  시각 모양을 맞추려고 서로 다른 학습 loss를 비교하지 않는다.

## 비교 조건과 축의 의미

기존 Fig. 2는 rendering budget을 맞춘 mapping 비교다. Fig. 3도 우선 이 조건과
일치시키면 초고의 주장이 이어진다. 단, 최종 render 총량만 같아서는 부족하다.
중간 work checkpoint의 입력 도착 범위를 기록하고, 가능하면 공통 causal packet과
packet별 work 배정으로 맞춘다. 이때 fixed frontend는 그 시점까지 추정한 causal
pose/depth를 제공해야 한다. 사후 보정 최종 trajectory replay를 strict online으로 부르지 않는다.

Iteration은 view 수/gradient accumulation이 방법별로 같음을 확인한 경우에만
주 x축으로 바꿀 수 있다. Render 수 역시 FLOPs나 초와 동치가 아니며 Gaussian 수와
loss overhead가 다를 수 있다. 이 도판의 주장은 work efficiency다.
실제 처리 시간 가속은 동일 장비/입력 재생 조건에서 측정한 elapsed-time 곡선으로
추가 검증한다. 최종 실행 시간을 iteration 비율로 나눠 시간 축을 합성하지 않는다.

15/30/60은 이 초고 그림에 모두 겹치지 않고, 본문 비교 표와 일치하는 예산 하나를
먼저 고정한다. 예산별 비교가 필요하면 별도 subplot 또는 후속 ablation으로 분리한다.

## 목표 도달 비용

우선 q는 baseline 최종 PSNR로 두는 endpoint-matching 설명이 직관적이다.
이는 사후 선정 목표임을 밝히고, 일반적인 수렴률 증명으로 확대하지 않는다.
양쪽 모두 같은 q의 최초 관측 도달 work를 구해
`saving = 100 * (1 - W_ours(q) / W_baseline(q))`로 계산한다.
Baseline의 전체 실행 예산을 W_baseline(q) 대신 사용하지 않는다.

관측점 사이 crossing은 구간만 알 수 있다. 보간 수치를 쓸 경우 추정임을 표시한다.
도달 후 다시 q 아래로 떨어지면 곡선에 그대로 드러내고 안정적 수렴이라고 쓰지 않는다.
목표 미달, 첫 checkpoint에서 이미 도달, 유지 여부 확인 불가는 별도로 기록한다.
곡선이 빠른 도달을 지지하지 않으면 속도 화살표/배율 없이 품질 추이만 제시한다.

## 장면과 렌더 선정

첫 후보는 Fig. 2와 연결되는 RPNG table_06. 단, 기존 Fig. 2는 큰 개선을 보이는
정성 예시로 선정됐으므로 이 장면을 전체 평균의 대표라고 단정하지 않는다.
가능하면 평가 대상 전체 장면의 곡선을 확보하고, 본문에는 선정 이유를 명시한
예시 장면을 두며 나머지는 부록에 둔다. seed는 사전 고정하거나 복수 seed 평균으로 표시한다.

아래 ROI는 Fig. 2의 동일 시점/영역을 우선 검토하되, 그 시점이 보여주는 영역을
두 방법 모두 관측한 중간 checkpoint가 있어야 refinement 예시로 해석할 수 있다.
해당 view가 너무 늦게 관측된다면 더 이른 공통 관측 영역에서 view/ROI를 고정한다.
Checkpoint는 곡선의 가장 큰 차이를 찾는 방식보다 공통 중간 work에서 먼저 정한다.

## 현재 확보한 근거와 필요한 자료

- Fig. 2 provenance: table_06, 양쪽 physical training renders 34,437.
  장면 전체 endpoint PSNR은 baseline 22.6822 / ours 24.4731 dB.
  단일 전시 이미지의 26.1271 / 31.2532 dB를 곡선 endpoint로 쓰면 안 된다.
- Fig. 2 provenance의 Carve는 false다. 같은 실행을 확장하면 현재 view-management
  통합 결과이며, Carve 포함 전체 구성의 결과를 의도한다면 해당 구성을 명시한 pair가 필요하다.
  PSNR 곡선으로 geometric convergence까지 주장하지 않는다.
- `ERCB_ablation/dense-supervision`의 곡선은 KF-only 대 KF+dense 실험으로,
  Ours 대 VIGS-SLAM 전체 방법의 곡선으로 재명명할 수 없다.
- 현재 감사한 자료에서는 해당 전체 방법 pair의 중간 PSNR/map을 확보하지 못했다.
  먼저 원래 run의 checkpoint 존재를 확인하고, 없으면 checkpoint 저장을 추가한 paired 실행이 필요하다.
- 약 20–30개 공통 work checkpoint를 권장한다. 이는 평가 시점일 뿐 topology나
  mapping phase를 바꾸는 조건이 아니다. 평가를 위해 EOS 후 추가 optimizer update를 하지 않는다.
- 로그: run/seed/config, held-out UID hash, input timestamp/prefix, training renders,
  optimizer steps, elapsed seconds, Gaussian 수, per-view PSNR, checkpoint 경로.
- 저장 map을 사후 평가해 평가 overhead가 온라인 처리량을 바꾸지 않도록 한다.
  저장 overhead도 계측하고, 실제 시간 주장은 별도로 검증한다.
