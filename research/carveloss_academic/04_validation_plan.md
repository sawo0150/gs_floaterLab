# 04 — 검증 계획: 최종 PSNR을 돌리기 전에 반증한다

> [01](01_current_formulation_audit.md) §5의 **메타 결함** — "지금 검증 수단이
> `끝까지 돌려서 PSNR 보기` 하나뿐이고, 그건 exp69에서 봤듯 run-to-run 노이즈
> (±0.24~0.33dB)와 구분이 안 된다" — 를 해결하는 것이 이 문서의 목적이다.
>
> 원칙: **싼 것부터, 그리고 각 단계는 통과 못 하면 다음 단계로 못 간다.**
> 앞 4단계는 3DGS 학습을 전혀 돌리지 않거나(P0~P2), 이미 있는 라벨 데이터만 쓴다(P3).
> strict streaming 런은 **마지막(P5)**에만 나온다.

---

## 0. 사다리 개요

| 단계 | 무엇을 반증하나 | 3DGS 학습 필요? | 예상 비용 | 대응 예측 |
|---|---|---|---|---|
| **P0** | 재현 하네스 — 로그된 ray를 재생할 수 있는가 | ✗ | 반나절 | (기반) |
| **P1** | 사후확률이 **보정되어 있는가** | ✗ | 분 단위 | E1 |
| **P2** | 상관 관측(결함 C) 진단이 **맞는가** | ✗ | 분 단위 | E2 |
| **P3** | floater **분류기로서** 현재 score보다 나은가 | ✗ (기존 라벨) | 시간 단위 | E3 |
| **P4** | 삭제 비용비 `C_del/C_keep`은 **얼마인가** | ✓ (배치) | 반나절 | E4, E5 |
| **P5** | strict streaming에서 **품질/기하 동시 비열등** | ✓ (스트리밍) | 1~2일 | 최종 |

**P1~P3을 통과 못 하면 P5는 돌리지 않는다.** 이게 이 계획의 핵심이다 —
exp69에서 낭비된 패턴(구현을 다 만들고 마지막에 end-to-end로만 판정 → 원인 불명 실패)을
반복하지 않기 위함이다.

---

## P0 — Ray 재생 하네스 (기반 작업)

**할 것:** VIGS 런 중 도착하는 SLAM depth ray를 그대로 덤프한다.
keyframe별 `(pose, K, depth map, depth 공분산/불확실성, timestamp)`.

**왜 이게 먼저인가:** P1~P3 전부가 "3DGS 없이 ray 통계만 갖고" 판정하는 실험이다.
ray를 파일로 떼어내는 순간 **실험이 초 단위로 반복 가능해지고, GPU도 필요 없어진다.**
현재는 모든 검증이 VIGS 전체 런에 묶여 있어서 한 번에 수십 분이 든다.

**산출물:** `rays_{scene}.npz` — 장면당 한 번만 만들면 재사용.
장면은 최소 2개(`aria1253`, `aria301_305`) — exp59의 교차 장면 실패를 처음부터 감시하기 위함.

**주의:** `σ_r`(depth 불확실성)을 함께 덤프해야 한다. 이게 §03의 핵심 입력인데,
**지금 VIGS 경로에서 이 값이 실제로 노출되는지 미확인이다.** DROID의 `disps` 분산이나
BA Hessian에서 나오는지 코드 확인이 P0의 실제 리스크. 없으면 대체안:
inverse-depth 잔차의 국소 분산으로 경험적 추정 → 그래도 상수보다는 낫다.

## P1 — 보정(calibration) 검사 [예측 E1]

가장 싸고 가장 결정적인 실험이다.

**설계:**
1. P0의 ray를 시간 순으로 절반(`t < T`)만 써서 voxel 사후 `p_free(v)`를 만든다.
2. 나머지 절반(`t ≥ T`, **held-out ray**)으로 각 voxel의 실제 자유/점유를 판정한다.
3. 예측확률을 10개 bin으로 나눠 **신뢰도 다이어그램**을 그린다.
4. **ECE(Expected Calibration Error)** 와 **Brier score**를 낸다.

**비교 대상 (같은 그림에 3개 곡선):**
- (a) 현재 `score = ρ · min(d_anchor/τ, 1)` — 확률로 주장한 적은 없지만 임계값으로 쓰이므로 그대로 올린다
- (b) 제안 사후 평균 `E[p_free]`, ESS 보정 **없이** (κ=1)
- (c) 제안 사후 평균, ESS 보정 **있음**

**판정:**
- **통과:** (c)의 ECE가 (a)보다 유의하게 작다.
- **기각:** (c)가 (a)보다 나쁘거나 같다 → 확률모형화의 첫 번째 약속이 깨진 것.
  이 경우 §03 전체를 재검토한다(그리고 그 사실 자체가 값진 결과다 —
  "이 문제에서는 count 휴리스틱이 이미 충분하다"는 결론).

> **이 실험이 왜 중요한가:** 현재 `gate_score=0.95`, `prune_score_min=0.50` 같은
> 임계값이 **무엇을 뜻하는지 아무도 모른다**는 게 [01 §1.2]의 결함 E였다.
> P1은 그 질문에 처음으로 숫자를 준다. 통과하든 기각하든 **지금 모르는 것을 알게 된다.**

## P2 — 상관 관측 진단 [예측 E2]

**가설(결함 C):** 30fps SLAM ray는 독립이 아니므로 count 기반 사후는 **과신**한다.

**설계:** P1의 (b)와 (c)를 직접 대비한다. 추가로 voxel을 **관측 방향 다양성**
(`S_v`의 고유값비)으로 층화해서 신뢰도 곡선을 따로 그린다.

**모형이 하는 구체적 예측:**
1. (b)의 곡선은 대각선 **위쪽으로 체계적 이탈**(과신)해야 한다.
2. 이탈 크기는 **방향 다양성이 낮은 층에서 더 커야 한다.**
3. (c)는 두 층 모두에서 대각선에 가까워야 한다.

**판정:**
- 1·2가 관측되면 결함 C 진단이 **확증**되고, Fisher LUT + `prune_persistence`가
  같은 병에 대한 두 패치였다는 [01 §2]의 주장도 함께 지지된다.
- 1이 관측되지 않으면 → **ESS 보정은 불필요하다.** §03에서 `κ_v=1`로 고정하고
  `S_v` 누적을 빼서 구현을 단순화한다. (이 역시 유용한 결과다.)

> **부수 산출물:** exp69에서 "1253은 좋아지고 12F는 나빠진" 비대칭이 관측됐다.
> 방향 다양성 층화 곡선을 장면별로 그리면 **그 비대칭이 관측 기하 차이로
> 설명되는지** 처음으로 확인할 수 있다.

## P3 — 분류기 성능 [예측 E3]

**할 것:** floater/비-floater가 라벨된 Gaussian 집합에 대해, 각 점수의 **AUC / PR 곡선**을 낸다.

**데이터:** 기존 수동 라벨 + region GT 자산
- `scripts/analysis/floater_metric_region.py`
- `scripts/analysis/build_floater_region.py`
- `share/floater_share/`, `floater_share_01_labels.zip`, `floater_share_02_region_gt.zip`

> ⚠ **중요한 제약(정직하게 기록):** exp55 문서에 따르면 `floater_metric_region.py`의
> 수동 라벨 GT는 **`data/03_rgb_3dgs_full`(ORB 배치 트랙) 전용**이다.
> 즉 P3는 **배치 장면에서만** 곧바로 돌릴 수 있고, VIGS 스트리밍 장면에는
> 라벨이 없다. 두 선택지:
> - (i) P3를 배치 장면에서 먼저 돌린다 — 점수 함수의 **분류 능력**은 표현 방식과
>   무관하므로 유효한 1차 관문이다. 권장.
> - (ii) VIGS 장면용 region GT를 새로 만든다(`build_floater_region.py` 재사용).
>   비용이 크므로 (i) 통과 후에만.

**비교:** 현재 `score` vs 제안 `Pr[p_free > p*]` vs (ablation) R1~R6 각각 하나씩 되돌린 버전.

**판정:**
- **통과:** 제안 AUC ≥ 현재 AUC. 기존 기록은 carve score AUC **0.98**이므로 기준이 높다.
  0.98을 넘기기는 어렵고, **동등하면서 임계값이 해석 가능해지는 것만으로도 이득**이다
  (§03 §6의 Bayes 규칙이 성립하려면 확률이어야 한다).
- **기각:** 제안 AUC가 유의하게 낮다 → 사후확률화가 정보를 잃은 것.
  R1~R6 ablation으로 **어느 가정이 손해였는지** 특정한다.

> **주의:** AUC 0.98은 이미 매우 높다. 따라서 P3의 진짜 관전 포인트는 AUC가 아니라
> **PR 곡선의 고정밀 구간**(false deletion을 거의 안 내는 동작점)이다.
> 삭제는 되돌릴 수 없으므로 recall보다 precision이 중요하다.

## P4 — 삭제 비용비 실측 [예측 E4, E5]

**할 것:** §03 §6의 `p_threshold = C_del/(C_del + C_keep)`를 **측정한다.**

**설계 (배치 장면, 학습된 지도 위에서):**
1. `C_del` — 수렴한 지도에서 **무작위** Gaussian을 N개(N을 여러 값으로) 지우고
   held-out PSNR 하락을 잰다 → "Gaussian 1개 삭제당 평균 손해".
2. `C_keep` — 라벨된 floater를 N개 지우고 floater 지표(region GT) 개선과
   held-out PSNR 변화를 잰다 → "floater 1개 존치당 손해".
3. 두 값에서 `p_threshold`를 계산한다.
4. **역산:** 현재 `prune_budget_total = 0.0075`가 암묵적으로 어떤 `p_threshold`에
   대응했는지 계산한다.

**판정:** 이건 통과/기각이 아니라 **측정**이다. 결과가 무엇이든 값지다:
- 역산값이 계산된 `p_threshold` 근처면 → 현재 예산은 우연히 합리적이었고,
  제안의 이득은 "장면 간 이식성"에 있다(exp59 문제).
- 크게 다르면 → 현재 설정이 체계적으로 편향돼 있었다는 직접 증거.

**동시에 E4 확인:** `Â_j`(밀도 가중)와 `score_j`(중심 delta)를 같은 지도에
적용해 **Gaussian 크기별 압력 분포**를 히스토그램으로 비교한다.
`Â_j`에서 큰 splat의 압력이 커지지 않으면 §03 §2.1 유도가 코드에 안 들어간 것이다.

## P5 — strict streaming end-to-end (마지막)

**전제:** P1·P2·P3 통과, P4 측정 완료.

**설계:** CLAUDE.md의 strict 계약을 그대로 지킨다 — RGB+IMU only, MPS 입력 0개,
fixed 1.5× (aria1253 기준 97.65초), tail update 0, fixed evaluator 252장 완전 제외.

**필수 조건 (exp69에서 배운 것):**
- **paired run**, 장면 **3개 이상**(`aria1253`, `aria301_305`, `12F`) — exp69는
  1253/305가 좋아졌는데 12F가 −0.918dB로 무너졌다. 한 장면 개선은 증거가 아니다.
- **장면별 재튜닝 금지.** 제안의 핵심 주장이 "상수를 측정량으로 바꾸면 이식된다"이므로,
  장면별로 손대는 순간 주장 자체가 반증된다.
- 각 조건 **2회 이상 반복** — 노이즈 ±0.24~0.33dB를 넘는지 봐야 한다.

**판정 기준 (사전 등록):**
- **품질 비열등:** 모든 장면에서 held-out PSNR이 control 대비 노이즈 폭 안이거나 우위.
- **기하 우위:** floater 지표가 최소 한 장면에서 유의 개선, **어느 장면에서도 악화 없음.**
  (exp69는 여기서 실패했다 — 305에서 676→726 악화.)
- **예산:** 1.5× 데드라인 준수, tail update 0.

**안전장치:** §03 §6의 `p_threshold → 1.0` 극한이 "아무것도 안 지움"이므로,
품질 회귀가 보이면 **플래그를 끄는 게 아니라 임계값을 올려서** 연속적으로 후퇴할 수 있다.
CLAUDE.md의 "27dB 미달 지도에 hard carve 먼저 넣지 않는다" 원칙과 정합적이다.

## 1. 이 계획이 기존 실패 패턴을 어떻게 피하는가

| 과거 패턴 | 어디서 | 이 계획의 대응 |
|---|---|---|
| 최종 PSNR로만 판정 → 노이즈와 구분 불가 | exp65 M4, exp69 | P1~P3이 **학습 없이** 중간 판정 |
| 한 장면에서 튜닝된 상수가 다른 장면에서 붕괴 | exp59 | 상수를 측정량으로(§03 §8) + P5에서 재튜닝 금지 |
| 구현 다 만들고 마지막에 원인 불명 실패 | exp69 | 사다리 순서 강제, 앞 단계 실패 시 중단 |
| 자체보고 신뢰 / 미계측을 "추정"으로 넘김 | memory 교훈 | P4는 통과/기각이 아니라 **실측** 단계로 명시 |
| 여러 축 동시 변경 | memory 교훈 | R1~R8이 각각 독립 ablation 축(§03 §7) |

## 2. 즉시 착수 가능한 최소 작업

가장 작은 첫 걸음은 **P0 + P1**이다. GPU도, VIGS 수정도, 학습도 필요 없다:

1. VIGS 런에서 ray를 한 번 덤프한다 (`aria1253`).
2. 순수 numpy로 voxel 통계 3종(현재 score / Beta κ=1 / Beta+ESS)을 만든다.
3. held-out ray로 신뢰도 다이어그램 하나를 그린다.

**이 그림 한 장이 "근거가 약하다"는 문제제기에 대한 첫 번째 숫자 답이 된다.**
그리고 이 그림이 나쁘게 나오면 — 즉 현재 `score`가 이미 잘 보정돼 있으면 —
§03 전체를 **싸게 기각**할 수 있다. 그게 이 순서의 진짜 목적이다.
